二、编排方式：主控与子会话怎么接
  • 主控：收消息 → 判类型 → 查库 → 拆活 → 派子会话 → 收结果 → 验数 → 交付。判断与验收不外包。
  • 子会话：一次一单，只干被派的那一段（取件、入库、采集、写表），不拍板、不改主控结论。
  • 通信：主控创建子会话并下发任务；子会话完成后回传结果。会话之间没有共享内存，靠任务说明与回传结果对齐。
  • 并发：可以同时派多条线，但没有常驻 worker 池；今天 57 份会话记忆说明会话多，不等于持续并行。
  • 人盯在哪：派活、收活、采信结论、对外交付，仍由主控会话里的人确认。
三、知识底座：双路还是三路，以及不可引用限制
  • 实际是三路：rag.py 字面（中文二元字组倒排）＋人工标签＋bge-m3 向量融合；不是双路。阈值 SIM_FLOOR 0.66、跨语言 0.58、OOV 0.50。
  • 无答案：三路都不过线返回「库内无相关内容」，不拿最接近的段落凑答案；放宽阈值才有命中的必须标注。
