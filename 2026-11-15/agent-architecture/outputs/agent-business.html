角色 A / 决策

用户

定方向、拍板、授权、给只有你能给的材料、做实测。

不做：查库、写稿、跑脚本、验数。这些不该回到你手上。

角色 B / 判断与验收

主控 agent

查底座、出判断、拆活、派子会话、验数、交付；对结果负责。

不做：替你决定「我是谁」、出镜、掏钱拍板、冒充法务。

角色 C / 执行

子会话

取件筛查、入库写库、经验采集、飞书读写；按主线派的一次性任务干。

不做：拍板、改主控结论、直接对你交付、常驻待命。

一、七道手逐步责任表
#这一步谁负责具体动作产出什么情况下停
1一句话需求用户说目标、给材料、划边界；缺什么由主控一次问清，不逐条追问。会话消息、附件缺只有你能给的材料；涉及拍板、花钱、签字。
2判任务类型主控分到判断 / 执行 / 取件 / 入库 / 采集 / 飞书写表六类；判断类先查库。内部路由，无文件任务跨了上游未完成层 → 报卡点，不硬做。
3查底座主控rag.py search 自然问句、catalog 按格找料、experience 查等级、记忆查既往决定。命中：路径＋段号／条号＋质量档库内无依据 → 只能写「库内无依据」，不许用印象补。
4拆活派发主控 → 子会话按四条线派：取件筛查、入库写库、经验采集、飞书表；一次一单，带验收条件。子会话任务说明子会话无权拍板；遇到边界只能回报，不自行改方向。
5执行子会话拉元数据、切段入库、写飞书行、采经验；只改自己那一段。中间产物、台账、飞书行结果不齐、数对不上、命中不确定 → 退回重做或标未验证。
6验数与自驳主控现场数（sqlite / csv / 文件数）、跑四道闸、判断自驳三轮、审查闸逐条回看。校验输出、修正后的结论数对不上、闸不过、三轮后仍站不住 → 撤回，不交付。
7交付主控结论写「给你看」；底座更新留在「我自己用」；飞书只写推进表与结论。结论页、底座更新、飞书行未验证、未数过、依赖未满足 → 不报完成，只报卡在哪。

四、必须停下来问人的四类（现行规则）
  • ① 待你确认：SOP 表里状态为「待你确认」的行，主控不许自行往下推。
  • ② 缺你的材料：证件、真名、案例授权、扫码登录——只有你能给，穷尽替代方案后一次提出。
  • ③ 花钱或签字：采购、投流、封面工具、正版书，全部先报再动。
  • ④ 规则冲突：表内两条规则打架时停下报冲突，不静默选一条。
  • 当前待拍板：账号类型（接活操盘手／卖工具的人）、第一条选题、199 诊断挂不挂、是否采购与投流、第一个真实案例。
  • 不该问人的：查库、写稿、跑脚本、数条数、格式整理——这些回到用户手上就是主控失职。
