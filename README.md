## 文档分两类（2026-11-15 写入）

- **给用户看的**：`05-给你看/`。只放结论、判断、钱与红线，看的人不需要知道过程。
- **我自己用的**：`00-战略与目标/`、`01-执行包/`、`02-调研与对标/`、`03-决策与复盘/`、`04-知识底座/`。按**查询方便**组织（按主题与用途分目录），不按读者分。

判据：一份文档如果改完要给人看，就去 `05-给你看/`；如果只是我自己下次开工要查，留在 00–04。同一件事两边都有时，结论放 05，过程留原处，不许两份都写成"结论"。

## 什么情况往哪找

- 要发第一条 → `01-执行包/`
- 要定方向、改计划 → `00-战略与目标/`
- 要找对标账号或爆款证据 → `02-调研与对标/`
- 要查某条结论凭什么成立 → `03-决策与复盘/`；理论依据与出处审计在 `04-知识底座/knowledge/`
- 要查平台机制、SOP、话术、复盘方法 → `04-知识底座/knowledge/`（`INDEX.md` 是总入口）
- 要看知识图谱 → `04-知识底座/图谱/index.html`
- 要翻原始截图、日志 → `06-素材与附件/`
- **要查作业进度、下一步做哪行** → `python3 03-决策与复盘/log_task.py next`（另有 `status`／`check`）
- **要查库里有什么、做检索、看入库情况** → `04-知识底座/rag/`（`kbase.db`），总入口 `04-知识底座/00-我用-检索入口.md`
- **要给人看的结论** → `05-给你看/`

## 注意

- `AGENTS.md` 是工作规则，仍在根目录。
- 话术、发布 SOP、复盘 SOP、进货清单、结论出处审计正续两份没有搬进 01/03：它们属于 `knowledge/`，按要求内部结构不拆不改，从 `04-知识底座/knowledge/INDEX.md` 进入。
- `knowledge/` 内的相对链接未改，仍按原结构互相引用。
- 项目顶层只放一级目录与规则文件。**读表导出的 `tbl*.ndjson` / `*.manifest.json` 不许落顶层**，临时件放 `work/feishu-dump/`，留档件放 `99-归档/飞书导出-<日期>/`（2026-11-15 已清理 138 个）。
- 根目录的 `书/` 是空目录，尚未确认用途，未删；确认无用后再清理。
