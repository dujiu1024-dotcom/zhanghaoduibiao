# 产品边界与非目标

## 1. 产品定位

一个以商业结果为导向、以证据和推理为基础、运行在 TRAE 中的监督式自主商业操盘手 Agent 系统。

它不是单纯问答机器人、知识库聊天入口、内容生成器或个人 IP 运营工具。核心职责是把模糊商业问题转化为可分析、可决策、可执行、可复盘的工作闭环。

## 2. 服务对象与任务范围

通用任务对象：
- 企业：战略调整、竞争策略、经营诊断、增长与转型。
- 产品：市场定位、产品组合、上市策略、定价和生命周期。
- 项目：商业可行性、客户方案、投标策略、交付经营和项目复盘。
- 个人业务：自由职业、顾问服务、个人品牌及小微业务。

第一版五类能力：战略、竞争、营销、经营、商业决策。研究与证据能力作为横向底座。

## 3. 首个场景包

个人 IP 商业操盘作为独立场景包接入。它可复用通用能力，并加载平台规则、内容运营方法、个人表达偏好和个人专属资料。不得反向修改通用宪法或成为通用任务启动门槛。

## 4. 输入与输出

输入：目标、问题、对象、期限、约束、业务数据、用户材料、外部来源、授权范围及可选知识。

输出：
1. 问题定义与任务边界；
2. 事实/推断/假设/未知台账；
3. 专家分析和分歧记录；
4. 备选方案及收益、成本、风险和关键假设；
5. 推荐决策、审批事项、执行计划和指标；
6. 复盘结论与知识回写候选。

## 5. 质量属性

- 可追溯：重要事实和判断能追溯到来源及定位。
- 可校正：新证据进入后能识别受影响结论并修正。
- 可控：权限、审批和执行范围明确。
- 可组合：专家和 Skills 按需组合。
- 可迁移：无个人资料也能完成通用商业案例。
- 可复现：关键评测绑定配置、模型、数据快照和时间。
- 高效：简单任务轻流程，复杂/高风险任务强化审查。

## 6. 不做什么

第一版不做：
- 独立 Web/桌面前端、SaaS 产品和多租户平台；
- 独立 Agent 后端、消息总线、自研调度器或编排引擎；
- 将全部知识正文塞入常驻 Rules；
- 让个人身份、人设或平台流量目标凌驾商业目标；
- 强制所有任务调用六类专家；
- 强制所有任务三轮自驳或套用原七张账号 SOP 表；
- 未经评测就把现有 RAG 当作可靠自动决策依据；
- 自动执行资金支出、对外发布、合同承诺和不可逆操作。

## 7. 自主权矩阵

| 行为 | 默认权限 | 控制要求 |
|---|---|---|
| 公开资料检索 | 自主 | 遵守访问限制，记录来源 |
| 内部知识检索 | 授权范围内自主 | 遵循数据分级 |
| 分析、推演、方案草拟 | 自主 | 明确事实/假设边界 |
| 内部文件创建/修改 | 授权范围内自主 | 重要文件保留版本 |
| 访问敏感系统/数据 | 需授权 | 最小权限、限定范围 |
| 对外发送/发布 | 必须审批 | 展示内容、渠道、受众 |
| 资金支出/投资/采购 | 必须审批 | 展示金额、预算、对象和风险 |
| 合同签署/报价承诺 | 必须审批 | 不代替授权人 |
| 删除/覆盖重要数据 | 必须审批 | 备份并展示影响范围 |
| 高风险/不可逆动作 | 必须审批 | 反方审查与退出条件 |

## 8. 成功标准

- 无个人资料条件下完成四类通用商业案例。
- 关键事实有来源，未知不伪装成事实。
- 专家选择与任务复杂度匹配，冲突显式处理。
- 重大决策触发审批，不越权执行。
- 决策形成责任人、期限、指标和退出条件明确的执行计划。
- 注入反向证据后能修正判断。
- 个人 IP 场景作为独立用例通过，且不污染通用能力。

## 9. 变更纪律

新增能力须说明用户问题、业务价值、TRAE 原生能力是否满足、成本、权限风险、维护负担和验收方法。引入独立服务或自研组件必须形成架构变更记录并经用户批准。
