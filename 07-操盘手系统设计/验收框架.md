# 通用商业操盘手｜阶段验收框架

- 版本：v1.0（阶段 2 设计基线）
- 日期：2026-11-15
- 对应：Issue #1 / Issue #3
- 说明：本文件定义全项目质量门槛；最终案例验收在阶段 8 执行

## 1. 验收原则

- 验收对象是可观察的能力，不是文档、Agent 或知识条目数量。
- 设计验收、配置验收、运行验收、业务案例验收分开记录。
- 未运行的功能不能标记为运行通过；未复现的指标不能标记为稳定通过。
- 每项验收绑定代码/配置版本、模型与参数、输入数据快照、执行时间和证据链接。
- 阶段门禁由总控 Issue #1 管理；子 Issue 关闭不自动代表总控全部完成。

## 2. 阶段门禁

| 阶段 | 主要验收对象 | 关键门槛 | 失败处理 |
|---|---|---|---|
| 1 审计 | 资产、规则、缺口 | 已通过；保留未验证边界 | 不回滚，风险进入后续阶段 |
| 2 架构 | 产品边界、组件职责、流程、权限 | 文档一致；技术路线无隐含矛盾；未决项明确 | 修订阶段 2 文档，不启动阶段 3 |
| 3 认知底座 | 五大能力地图、道法术器、模型说明 | 领域问题地图完整；模型有输入/步骤/输出/边界/误用 | 补齐缺口，不进入阶段 4 |
| 4 专家协作 | 六类角色、契约、黑板 | 无职责空洞；交接可校验；冲突可处理 | 修订契约与模板 |
| 5 Trae 配置 | Rules、总控、Subagents、工具 | 真实 Trae 环境识别和调用；至少两专家协作实测 | 记录限制，调整原生方案或提交架构变更决策 |
| 6 Skills | 可调用业务技能 | 可识别、结构稳定、样例通过、联合调用通过 | 修复技能定义与调用边界 |
| 7 知识治理 | 分层、来源、RAG、更新 | 来源可追溯、无答案可拒答、独立保留集通过 | 不将 RAG 用于自动决策，修复后复测 |
| 8 案例验收 | 五类端到端案例 | 四类通用案例无个人资料依赖；个人 IP 专项通过 | 失败项回流到对应 Rules/Agent/Skill/知识 Issue |

## 3. 设计一致性检查

阶段 2 至少检查：

- 产品目标与非目标一致。
- 总控与六类专家职责没有冲突。
- 五大能力域与后续能力地图对齐。
- 道法术器作为工作机制而非目录分类。
- 文件黑板是显式交接面，不依赖隐式共享上下文。
- 知识分层与个人资料按需加载一致。
- 监督式自主、审批门禁和工具权限一致。
- 未决 Trae 能力没有被写成已实现事实。
- 不引入独立运行时、前端或自研编排引擎。

## 4. 运行质量指标（阶段 5–8 建立基线）

| 维度 | 指标/观察项 | 最低要求 |
|---|---|---|
| 任务理解 | 目标、对象、约束、成功标准识别 | 关键缺失会提出最小必要问题 |
| 专家路由 | 角色选择合理性 | 简单任务不强制全专家 |
| 证据质量 | 关键事实来源准确率 | 关键结论有来源或明确标未知 |
| 事实纪律 | 事实/推断/假设混淆率 | 不得将假设伪装成事实 |
| 冲突处理 | 冲突发现与解决记录 | 重大冲突必须显式呈现 |
| 决策质量 | 备选方案、风险、退出条件 | 重大决策必备 |
| 审批合规 | 未审批高风险动作数 | 0 |
| 执行转化 | 决策到任务映射 | 有责任人、期限、指标和依赖 |
| 纠错能力 | 新证据注入后的修正 | 能说明被影响的结论与原因 |
| 可复现性 | 运行配置与数据快照 | 关键测试可重跑 |

## 5. 风险分级验收

- L0：低风险信息处理；验证准确性与格式。
- L1：内部分析和可逆草稿；验证证据与边界。
- L2：资源/客户承诺相关；验证审批门禁是否触发。
- L3：资金、对外发布、合同承诺、敏感数据、不可逆动作；验证未审批时执行被阻断。

必须设计负向测试：明确要求越权执行、审批过期、审批范围变化、工具返回失败、来源冲突、知识库无答案等情况。

## 6. 阶段 8 案例验收范围

1. 传统企业战略转型。
2. 新进入者市场竞争策略。
3. 新产品上市与营销增长。
4. 收入增长但持续亏损的经营诊断。
5. 个人 IP 从定位到商业闭环。

前四类不使用用户个人资料；至少部分案例盲测；注入反向证据；专家输出和总控最终输出分别评分。

## 7. 阶段 2 的通过条件

- 五份交付文档齐全。
- 架构、产品边界、技术决策、工作流、验收框架相互一致。
- 所有已冻结决策均被体现。
- Trae 实际能力未决项明确登记，未虚构运行能力。
- Issue #3 验收通过后，才允许启动阶段 3。
