# 通用商业操盘手｜阶段验收框架

## 1. 验收原则

验收能力，不验收文档数量、Agent 数量或知识条目数量。设计验收、配置验收、运行验收和业务案例验收分开记录。未运行的功能不能标记运行通过；所有运行验收统一放在项目末尾进行。

每项评测记录配置版本、模型/参数、输入数据快照、执行时间、预期结果、实际结果和证据链接。

## 2. 阶段门禁

| 阶段 | 验收对象 | 关键门槛 | 失败处理 |
|---|---|---|---|
| 1 审计 | 资产、规则、缺口 | 审计交付和复验通过 | 已完成 |
| 2 架构 | 产品边界、职责、流程、权限 | 文档一致，未决项明确 | 修订设计 |
| 3 认知底座 | 五大能力地图、道法术器、模型说明 | 问题地图完整，模型含输入/步骤/输出/边界/误用 | 补齐覆盖 |
| 4 专家协作 | 六类角色、契约、黑板 | 无职责空洞，交接可校验，冲突可处理 | 修订契约 |
| 5 TRAE 配置 | Rules、总控、Subagents、工具配置 | 配置文件符合官方格式；运行验收延后 | 修复静态配置；运行项留末尾 |
| 6 Skills | 可调用业务技能 | 每个 Skill 有触发条件、步骤、输出、示例和检查 | 修订技能 |
| 7 知识治理 | 分层、来源、RAG、更新 | 可追溯、无答案策略、独立评测集与版本记录 | 保留风险，不宣称通过 |
| 8 案例验收 | 五类端到端案例 | 四类通用案例无个人资料依赖，个人 IP 专项通过 | 回流对应资产 |

## 3. 设计一致性检查

- 产品目标与非目标一致。
- 总控与六类专家职责无空洞/冲突。
- 五大能力域与认知地图对齐。
- 道法术器是工作机制，不是知识目录。
- 文件黑板是显式交接面。
- 个人知识按需加载。
- 监督式自主、审批门禁和工具权限一致。
- TRAE 未验证能力不写成已运行。
- 不引入独立运行时或自研编排引擎。

## 4. 运行质量指标（项目末尾统一验收）

| 维度 | 检查项 | 目标 |
|---|---|---|
| 任务理解 | 目标、对象、约束、成功标准 | 缺失时问最小必要问题 |
| 专家路由 | 角色选择合理性 | 简单任务不强制全专家 |
| 证据质量 | 关键事实来源准确性 | 关键结论有来源或标未知 |
| 事实纪律 | 事实/推断/假设混淆 | 不得将假设写成事实 |
| 冲突处理 | 冲突发现与解决记录 | 重大冲突显式呈现 |
| 决策质量 | 备选、风险、退出条件 | 重大决策必备 |
| 审批合规 | 未审批高风险动作 | 0 |
| 执行转化 | 决策到任务映射 | 有责任人、期限、指标 |
| 纠错能力 | 反向证据注入 | 能修正受影响结论 |
| 可复现性 | 配置与数据快照 | 关键测试可重跑 |

## 5. 风险负向测试

至少包括：要求越权执行、审批过期、审批范围变化、工具失败、来源冲突、知识库无答案、个人知识不可用、专家意见矛盾、预算超限和执行中前提变化。

## 6. 端到端案例范围

1. 传统企业战略转型。
2. 新进入者市场竞争策略。
3. 新产品上市与营销增长。
4. 收入增长但持续亏损的经营诊断。
5. 个人 IP 从定位到商业闭环。

前四类不使用用户个人资料；至少部分盲测；注入反向证据；专家输出和总控最终输出分别评分。

## 7. 项目末尾统一真机验收清单

- TRAE 项目规则加载。
- 六类 Subagent 识别与调用。
- 至少两专家协作与文件交接。
- Skills 识别与联合调用。
- MCP 权限和失败处理。
- 人工审批门禁。
- RAG 评测和无答案拒答。
- 五类案例端到端执行。

本清单只定义验收项目，不代表已执行。
