# 商业操盘手 Agent｜待配置包

> 状态：待用户在 Trae CN 3.4.20 中手动配置与真机验收。此目录是配置材料，不会因存在于仓库而自动成为 Trae Agent，也不代表已加载或运行通过。

## 目标

将现有项目治理资产整理成可直接用于 Trae 配置的材料，供用户自行创建/配置总控 Agent，并关联六类专家 Subagent。

## 现有资产与本包的关系

本包不是重建一套治理体系，而是面向 Trae 配置界面的可复制版本。仓库长期规则仍以根目录 `AGENTS.md`、`.trae/rules/00-commercial-constitution.md`、`.trae/rules/10-case-blackboard.md` 和现有 `.trae/agents/` 为准。发生冲突时，项目宪法、安全边界和用户最新明确指令优先。

## 文件清单

| 文件 | 放置/用途 |
|---|---|
| `01-总控Agent身份与系统提示词.md` | 配置总控 Agent 的名称、身份、职责及核心提示词 |
| `02-强制工作流程.md` | 配置总控执行流程、专家路由和交付闭环 |
| `03-权限与审批规则.md` | 配置人工审批边界；同时需在 Trae 工具权限中设置最小权限 |
| `04-六类专家配置对照.md` | 对照仓库现有六个 Subagent，不重复新造角色 |
| `05-真机配置验收清单.md` | 用户配置后逐项测试并记录证据 |

## 用户配置顺序

1. 在 Trae CN 3.4.20 打开本项目仓库，并确认工作区已设为可信。
2. 检查项目 Rules 是否加载；按项目既有配置启用 Subagents 功能。
3. 在 Trae 支持的自定义 Agent 配置入口创建总控 Agent，复制文件 01 的名称、描述和提示词。
4. 按文件 04 检查六个 Subagent 是否可见、可被总控调用；不要仅凭文件存在判定已加载。
5. 对照文件 03 设置最小工具权限与手动审批。提示词不能代替平台权限控制。
6. 按文件 05 执行真机验收。保留每项输入、输出、可见调用事件、权限弹窗和失败记录。
7. 验收通过前，只能标记为“待配置”或“已配置待验证”，不得标记为“已上线”。

## 重要兼容性说明

本包以 Trae CN 3.4.20 为目标环境。Trae 不同版本、不同 Agent 入口的能力可能不同。若该版本不支持用户希望的自定义总控 Agent 配置方式，不要伪造成功；记录实际界面和限制，退回项目已设计的“内置 Agent 调用 Subagent”路径，并按真机结果调整。

## 专家文件写入边界

专家只能新建总控派单明确指定的独立交付文件，写入 `work/cases/<case_id>/04-专家分析/`；写入前确认目标不存在；禁止覆盖共享黑板、总控文件或其他专家产物。Write 不是路径级沙箱；Trae CN 3.4.20 未验证前，必须由总控审查实际写入记录。
本配置包的权限说明与仓库 `.trae/agents/` 六类专家文件保持一致；若出现不一致，以更严格的项目宪法和专家 Write 边界为准。
