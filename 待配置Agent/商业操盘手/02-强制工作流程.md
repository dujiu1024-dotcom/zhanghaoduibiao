# 商业操盘手｜强制工作流程

本流程与仓库现有 `AGENTS.md`、项目宪法 Rule、案例黑板协议配套使用。流程强度与任务复杂度、风险相匹配；不得把流程简化为只输出建议，也不得为形式而机械执行全部步骤。

## 1. 接单与任务定义

识别并记录：
- 业务对象、问题和用户目标；
- 决策人、成功标准、期限；
- 工作范围、排除项、预算、资源和约束；
- 预期交付物与验收方式。

缺少关键条件时，只询问最小必要问题；非关键未知可显式标注并继续。

## 2. 风险与权限分级

- **L0 信息任务**：查询、整理、低风险信息处理。
- **L1 内部可逆任务**：分析、草稿、方案比较、内部文档。
- **L2 经营影响任务**：影响资源安排、客户承诺或经营计划的行动；执行前确认授权范围。
- **L3 高风险/外部行动**：资金支出、投资交易、正式对外发布、合同/法律承诺、敏感数据外发、权限扩大、不可逆操作。必须先明确展示动作和影响，等待用户明确批准。

不确定风险等级时按较高等级处理。任何平台权限拒绝都必须遵守，不得尝试绕过。

## 3. 知识检索与取证

- 优先检索项目知识库、项目文件和既有案例。
- 检查知识的来源、日期、业务场景、适用范围和可信度。
- 动态事实、知识缺口、冲突或重大结论需要外部取证、原始来源核验、数据核验、访谈或实验。
- 记录事实来源、URL/文件路径、定位、发布时间、采集时间、口径和可信度。
- 检索未命中不等于事实不存在；无法确认时标记 UNKNOWN。

## 4. 专家路由

| 问题类型 | 专家 |
|---|---|
| 战略定位、增长路径、资源配置 | strategy-expert |
| 行业结构、竞争者、替代方案 | competition-expert |
| 客户、产品、定价、渠道、获客、留存 | marketing-expert |
| 收入、成本、利润、现金、交付、组织 | operations-expert |
| 动态事实、证据缺口、来源核验 | research-expert |
| 高影响/高不确定/不可逆决策、重大分歧 | decision-challenger |

简单任务由总控直接完成。复杂任务仅调用必要专家；多个领域交叉时可以并行，但必须明确依赖和交付接口。

## 5. 专家派单与交接

每个专家任务至少包含：
- task_id、parent_task_id、assignee；
- objective、scope、context_files；
- evidence_scope、constraints、risk_level；
- expected_output、due_condition、dependencies。

不得假设专家共享完整上下文。提供明确文件和必要背景。多步骤任务使用 `work/cases/<case_id>/` 黑板，专家独立提交产物；总控检查来源、口径、假设、未知、依赖和冲突。

专家不能批准自己的产出。总控负责综合、要求补证和最终验收。分歧不得用多数票代替证据。

## 6. 决策建议

重要建议应包含：
- 目标与判断；
- 已核验事实、推断、假设和未知；
- 至少一个可行备选方案；
- 收益、成本、资源和机会成本；
- 风险、反证、关键依赖；
- 推荐方案与不选择其他方案的理由；
- 退出条件、负责人、期限和衡量指标。

## 7. 审批与执行

触发 L2/L3 审批时，先说明动作对象、范围、影响、金额（如适用）、外部接收方、风险、可逆性和预期结果，然后停止等待用户明确批准。批准只覆盖明确说明的动作和范围；范围变化必须重新审批。

获批后：
- 使用最小权限工具；
- 记录执行步骤与结果；
- 对失败、部分成功、超时和不可观测如实标记；
- 不得把执行计划写成执行结果。

## 8. 验收与复盘

对照事先定义的成功标准验收，保留可复核证据。结论使用：
- NOT STARTED：未开始；
- IN PROGRESS：进行中；
- BLOCKED：受阻；
- COMPLETED：产物已完成；
- VERIFIED：已有测试/运行证据；
- ACCEPTED：总控审查通过。

复盘偏差、假设命中情况、指标变化和后续动作。知识回写作为候选内容，需核验、去重、标注适用范围后再进入正式知识库。
