# 示例查询：15–30 秒 + 前三秒有字幕 + 需求信号 ≥ 求教程

数据库：`bbase.db`｜首次执行 2026-11-14｜**2026-11-14 修订：改用 `has_subtitle` 列重跑**

---

## 零、这版改了什么

上一版用 `first3_visual LIKE '%字幕%'` 判「前三秒有字幕」，**这条判定是错的**：它在 id 61 上命中的是画面描述里的「**无**字幕」三个字，把「没有字幕」当成了「有字幕」。

已加 `has_subtitle` 布尔列（1=有字幕条 / 0=无 / NULL=未判读），判定规则写在 `build_bbase.py:derive_has_subtitle()`：前三秒画面上有成行的字幕或文字条（台词字幕、片名字幕条、花字标题）记 1；纯品牌角标、整屏无文字记 0。

---

## 一、查询（修订版）

```sql
SELECT account AS 账号,
       raw_title AS 标题,
       duration_sec AS 时长秒,
       first3_visual AS 前三秒画面,
       demand_level AS 需求信号
FROM samples
WHERE duration_sec BETWEEN 15 AND 30
  AND has_subtitle = 1
  AND demand_level IN ('求定制/求代做', '求教程/求方法');
```

## 五、结论

1. **SQL 与数据都通了**：三个条件各自都能筛出真实行，`has_subtitle` 可正常用于判定。
2. **剩 0 条只因为样本不相交**：5 条短视频里唯一有字幕的（id 55）没有需求信号；2 条有求教程信号的（40、51）都是中长视频。
3. **要这条查询出数，还差 2–3 条「15–30 秒 + 有字幕 + 评论区求教程」的样本**。这是取样缺口，不是库结构缺口。
4. 顺带修掉一个会长期误导的坑：`LIKE '%字幕%'` 对「无字幕」同样成立，**任何时候都不要用它判有无字幕**，一律用 `has_subtitle`。
