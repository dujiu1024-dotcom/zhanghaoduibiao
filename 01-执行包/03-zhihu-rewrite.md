# 脚本转知乎（同步件，不运营）

定位：同稿机械改写，只同步不运营。上限 800 字、20 分钟，不新增判断、不加小标题、不用提问收尾。改写只做三件事：补主语、并短句、去口语连接词。

## 一、改写规则

| 改写处 | 规则 | 示例 |
|---|---|---|
| 开头要不要保留悬念 | 保留，但悬念必须来自事实矛盾，不用“你有没有遇到过”这类设问；第一段把时间、动作、异常结果摆出来 | 口播“17 点 34 分，它把字打进了搜索框”改成：“17:34，它把字打进了搜索框，随后报‘未找到目标元素’。” |
| 时间线怎么展开 | 每个时间点单独成段，按“时间 + 动作 + 结果”写；不补心理、不补环境 | “17:35，它换了一种找法，按位置找。这一次，通过了。” |
| 口播的短句怎么变书面句 | 合并短句，保留时间和数字；删掉“然后、就、才”，改用“随后、这一次、但” | “它改用按位置找，第二次通过。” |
| 结尾判断放在哪 | 判断放最后，事实摊完才下判断；只写一句，不提问 | 脚本 A／B 二选一，原样搬过来 |
| 工序上限 | ≤800 字，不加小标题，不增观点，20 分钟内改完 | 超出就删段，不扩写 |

## 二、知乎成稿

### 为什么有些 AI 智能体显示“任务完成”，实际却没有做完？

先看一段记录。

17:34，它把字打进了搜索框，随后报“未找到目标元素”。

17:35，它换了一种找法，按位置找。这一次，通过了。

17:37，同一个晚上，它被一条夜间规则拦住：夜间未授权，清单外要动手的事转成待办。

这一场的第 3 步，失败了。

整场结果一栏，仍然写着：成功。

把这几条记录放在一起，问题就出来了：一场第 3 步失败的任务，为什么最后会记成功？

“成功”和“失败”并不矛盾。一个记的是整场有没有跑完，一个记的是每一步有没有做成。终点到了，结果就写成功；可那一步为什么失败、失败之后有没有人处理，记录里不回答。

17:34 的动作是把字打进搜索框，结果是没有找到目标元素；17:35 换了一种找法，通过了；17:37 的动作不是找，而是被拦。三段放在一起，才看得出差别：前两次是找不找得到，第三次是让不让做。

最值得看的不是 17:34，也不是 17:35，而是 17:37。它在一套规则里动作：规则允许的，它做；规则没授权的，它停。边界本身不是坏事，问题在于边界触发之后，结果栏仍然写成功，边界就被藏起来了。

整场仍记成功，只说明这场跑完了，不说明每一步都做成了。

如果你手里也有一条显示“成功”的记录，先确认结果栏记的是整场还是单步；再看步骤表里有没有报错、换法、拦截；最后把失败步骤和整场结果并排看。

这条记录之所以值得看，不是因为失败本身，而是因为失败和成功被同时写了下来。很多记录只留下后者，前者被覆盖，复盘就无从下手。

（结尾二选一，与口播同一句，不叠加）
A：它没做错，是我规矩没写全。
B：我定的规矩，把自己也框住了。

## 三、哪些脚本适合转知乎，哪些不适合

| 判断维度 | 适合 | 不适合 |
|---|---|---|
| 有没有判断 | 结尾能落成一句可争论的结论，如“整场成功不等于每一步做成” | 只有“气死”“好笑”“无语”，没有结论 |
| 有没有可核对的信息 | 有时间、数字、步骤，如 17:34、17:35、17:37、第 3 步 | 只有“很久”“很多”“特别”，没有具体值 |
| 有没有反常识结果 | 第 3 步失败，整场却记成功 | 结果符合预期，没有落差 |
| 有没有完整因果链 | 能解释“为什么成功和失败同时出现” | 只有结果，没有过程；或者只有过程，没有判断 |
| 能不能回答一个具体问题 | 能回答“怎么判断智能体真做完了” | 只能回答“我今天做了什么”，读者没有问题可代入 |
| 是否依赖画面 | 文字能独立成立，画面只是证据 | 主要靠表情、音效、剪辑节奏，转成文字就散 |
| 能不能撑到 800 字 | 有 3 个以上信息层次，能展开 | 只有一个梗、一句金句，展开就重复 |

一句话：**有判断、有数字、有反常识结论的脚本适合转；纯情绪、纯过程流水账的脚本不适合。**
