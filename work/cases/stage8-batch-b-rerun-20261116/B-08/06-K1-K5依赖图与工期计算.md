## 1. K1-K5 依赖图

```
          ┌── K1（竞品普查）[无前置] ─────────┐
          │                                     │
          ├── K3（渠道合作）[依赖 K1 市场结构] ─┤
          │                                     │
    K5（资源核查）[无前置] ────────────────────┼── 决策汇总结论
          │                                     │
          ├── K2（租金可得性）[依赖 K1 商圈列表 + K5 现金流前提] ──┘
          │
          └── K4（消费者偏好）[无前置，可与 K1 并行] ──────────────┘
```

**关键路径识别**：

| K 步骤 | 前置依赖 | 后置依赖 | 关键路径角色 |
|---|---|---|---|
| K5 | **无**（纯内部） | K2 必须知道"可用于开店投资的现金流有多少"才能判断租金是否可承受 | 关键路径起点 |
| K1 | **无**（公开信息） | K2 需要商圈列表才能询价；K3 需要市场结构才能确定渠道策略 | 非关键路径（K5 并行启动） |
| K2 | **K5 + K1** | 无 | **关键路径的第二环节** |
| K3 | **K1** | 无 | 非关键路径 |
| K4 | **无**（桌面端） | 无 | 非关键路径（桌面端可立即开始，街头问卷视资源决定） |

## 2. 工期估计（全部 MODEL-PROPOSED 示例值，非固定值）

以下所有工期数字均为 **MODEL-PROPOSED** 基线估计，基于"内部人员利用公开信息执行"的假设。若委托外部、现场走访受限或商圈面积大于预期，工期需相应调整。

| K 步骤 | 最短工期 | 最长工期 | 前置条件 | 关键路径 |
|---|---:|---:|---|---|
| K5 资源核查 | 1 天 | 2 天 | 无 | ✅（关键路径起点） |
| K1 竞品普查 | 3 天 | 5 天 | 无 | ❌（与 K5 并行启动，不阻塞 K2） |
| K2 租金可得性 | 2 天 | 4 天 | **K1 商圈列表 + K5 现金流前提** | ✅（关键路径第二环节） |
| K3 渠道合作 | 3 天 | 5 天 | K1 市场结构 | ❌ |
| K4 消费者偏好 | 4 天 | 7 天 | 无（桌面端） | ❌ |

## 3. 关键路径工期计算

**关键路径** = K5（1-2 天）+ K2（2-4 天）= **3-6 天**

加 **20% 缓冲系数**（MODEL-PROPOSED：应对信息不足、对接延迟、商圈面积超出预期等意外）→ **4-7 天**

**非关键路径的最大工期** = max(K1, K3, K4) = 5-7 天

因此 **全部取证完成的时间窗口** = max(关键路径工期 + 缓冲, 非关键路径最大工期) = **4-7 天**

**不得** 将各 K 步骤工期直接相加（1+3+2+3+4=13 天）——这是 v1.1 独立复核 B08-R2 指出的错误。各步骤是并行执行的，工期取关键路径值，不取算术和。

## 4. 分批启动策略

为缩短实际总工期，建议将 K1-K5 分成 **两批** 启动：

### 第一批（Day 0 启动，无前置依赖，可立即开始）

| K 步骤 | 动作 | 审批门槛 |
|---|---|---|
| K5 | 内部财务对账，确认现金流分解、供应链覆盖、人员抽调 | **无**（纯内部动作） |
| K1 | 桌面端搜索大众点评/美团，步行走访核心商圈 | **无**（公开场所，内部人员） |
| K4（桌面端部分） | 美团/大众点评顾客评价关键词聚类 | **无**（公开数据） |

预计第一批在 **3-5 天内** 可形成初步结论（K5 最快 1-2 天出结果）。

### 第二批（第一批初步结论后启动）

| K 步骤 | 启动条件 | 审批门槛 |
|---|---|---|
| K2 | K1 给出候选商圈列表 + K5 给出现金流数字 | 仅公开信息，内部执行——**无审批** |
| K3 | K1 给出市场结构线索（判断是否需要渠道合作） | 仅电话初步接触，不签约——**无审批** |
| K4（街头问卷部分） | 视 K1/K2 结果决定是否需要 | 涉及个人信息处理——**需审批** |

**第二批启动后，K2 需 2-4 天、K3 需 3-5 天，二者并行执行。**

## 5. 四要素核验（K1-K5 逐条）

v1.1 规范 §7.3 要求每条 K 步骤独立呈现四要素：需要的数据、取得方法、责任角色、决策用途。决策用途必须具体说明该数据如何影响 A/B/C 中的选择或某项门槛。

### K1 四要素核验 ✅

| 要素 | 内容 |
|---|---|
| 需要的数据 | 当地烘焙品牌清单、各品牌门店数、核心商圈内竞品密度、各品牌定位线索 |
| 取得方法 | ① 桌面端：大众点评/美团/饿了么检索门店列表；② 步行走访核心商圈 |
| 责任角色 | 经营团队内部人员 |
| **决策用途** | ① 若竞品密度远低于预期 → 方案 A 风险下降；② 若密度远高于预期 → 方案 B 或 C 优先级上升；③ 若单一品牌垄断且无空铺 → 直接触发退出条件 E2 |

### K2 四要素核验 ✅

| 要素 | 内容 |
|---|---|
| 需要的数据 | 核心商圈租金报价、可用面积、免租期 |
| 取得方法 | ① 公开商业地产中介电话咨询；② 派员现场走访 |
| 责任角色 | 经营团队内部人员 |
| **决策用途** | ① 若租金显著低于战略专家隐性假设 → H3（6 个月盈亏平衡）概率上升，方案 A 可成立；② 若租金超出现金流能力 → 直接触发退出条件 E3；③ 若租金中等 → 需重新计算单店投资额后再判断 |

### K3 四要素核验 ✅

| 要素 | 内容 |
|---|---|
| 需要的数据 | 当地可合作渠道清单、合作条款（费用、分成、数据权限） |
| 取得方法 | ① 桌面端检索当地生鲜连锁/精品超市；② 电话初步接触 |
| 责任角色 | 经营团队内部人员 |
| **决策用途** | ① 若存在可合作渠道 → 方案 B 可行；② 若不存在任何渠道 → 方案 B 直接不可行，决策收窄到 A 或 C；③ 若渠道费用过高 → 方案 B 成本上升，需重新比较 |

### K4 四要素核验 ✅

| 要素 | 内容 |
|---|---|
| 需要的数据 | 当地消费者烘焙产品价位区间、偏好品类、新品牌接受度线索 |
| 取得方法 | ① 桌面端：美团/大众点评评价聚类；② 可选：街头访谈 |
| 责任角色 | 经营团队内部人员 |
| **决策用途** | ① 若消费者偏好与我方现有产品结构显著不同 → 方案 A/B 的价值主张都需要重新设计；② 若偏好可匹配 → 区分"试点成功但直营失败"的场景风险下降 |

### K5 四要素核验 ✅

| 要素 | 内容 |
|---|---|
| 需要的数据 | ① 现金精确分解（运营 vs 投资）；② 供应链覆盖成本；③ 可抽调人力 |
| 取得方法 | 内部财务对账 |
| 责任角色 | 财务部门（内部） |
| **决策用途** | ① **是所有方案的前置约束**：若现金流 < 3 个月 → 直接触发 E1，全部转为 C；② 若供应链无法覆盖 → 方案 A/B 都不可行；③ 若人力不足 → 方案 A（2 家同时开）需拆分为 1 家先开 |

## 7. 与 v1.1 独立复核（B08-R2）的对比

| v1.1 问题 | 本轮修订 |
|---|---|
| "K1=2-3 天、K2=3-5 天、K3=3-7 天、K5=1-3 天……得出'全部取证 10-14 天'" | 本轮先建立依赖图，识别关键路径 K5→K2（K1 并行），关键路径工期 = max(K5+K2, max(K1,K3,K4)) × 缓冲，得出 4-7 天 |
| 未明确并行/串行关系 | 本轮分两批启动策略，第一批 K5/K1/K4 并行，第二批 K2/K3 依赖 K1 初步结论后并行 |
| 无依赖图 | 本轮明确给出 ASCII 依赖图和依赖说明 |
| 总工期直接相加 | 本轮严格取关键路径值，**没有** 将各 K 步骤工期算术和作为总工期 |
