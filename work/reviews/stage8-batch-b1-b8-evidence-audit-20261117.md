## 3. Skill 与专家调用证据边界

PR #55 的 B1–B8 Skill 状态文件反复说明：执行者手动读取并遵循 `SKILL.md`，但无法观察 Trae 原生 Skill 的加载/触发事件。部分案例明确说明本轮是独立会话执行器直办，而非专家 Subagent 运行时。

因此必须区分：
- **文件可读/规则被手动参照**：有文件和执行者文字声明支持；
- **Skill 被 Trae 运行时加载**：NOT_OBSERVABLE；
- **总控实际调用六类专家 Subagent**：未见可核验调用事件/原始返回，NOT_VERIFIED；
- **输出内容符合某个专家的分析框架**：可以作为文本质量样本审查，但不等于证明专家 Agent 被调用。

PR #55 中 B-08 的调用事件记录明确将调用可观测性标记为 NOT_OBSERVABLE，Subagent 原始输出文件也说明无法确认总控是否调用任何专家。不得将这些“不可观测说明文件”解释为调用成功证据。

## 4. B-08 K1–K5 工期依赖计算仍存在公式错误

复核对象：`B-08/06-K1-K5依赖图与工期计算.md`。

该文件自身列明：
- K1：无前置，3–5 天；
- K5：无前置，1–2 天；
- K2：前置条件为 **K1 商圈列表 + K5 现金流前提**，2–4 天；
- K3：依赖 K1，3–5 天；
- K4：无前置，4–7 天。

因此依赖关系是：
- K1 → K2；
- K5 → K2；
- K1 → K3；
- K4 独立并行。

文件却在第 3 节使用“关键路径 = K5（1–2 天）+ K2（2–4 天）”并把“非关键路径最大工期”写为 max(K1,K3,K4)=5–7 天。该算法遗漏了 K2 对 K1 的依赖，也遗漏了 K3 对 K1 的依赖，不能与其第 1 节依赖图/依赖表同时成立。

按该文件所列依赖和区间，正确表达式应为：

`T = max(K1 + K3, max(K1, K5) + K2, K4)`

按区间端点计算：
- K1 + K3：6–10 天；
- max(K1,K5) + K2：5–9 天；
- K4：4–7 天；
- 总工期区间：**6–10 天**（分别取各路径最短/最长端点的最大值）。

这只是基于 PR #55 自己列出的 MODEL-PROPOSED 工期区间进行的数学复算，不是实际项目工期承诺。该发现意味着 B-08 声称“关键路径计算已修复/通过”尚不能接受，应修正依赖图、公式、说明和全量数字审计中的对应条目，并重新独立复核。
