### 1.2 依赖图与公式不一致

PR #59 的图示称 K5 先行，之后 K1/K2/K3 并行；K4 与 K2 同步/部分重叠。其公式却为：

`总工期 = max(K1 + K3, max(K1, K5) + K2, K4)`

至少存在以下问题：

1. 若 K5 是 K1/K2/K3 的前置步骤，`K1 + K3` 这条路径漏计 K5。
2. 图示称 K1/K2/K3 并行，但公式又将 K1 与 K3 串行相加；并行关系和公式口径相冲突。
3. “K4 与 K2 同步/部分重叠”没有给出可计算的开始条件、结束条件或重叠区间，不能直接将 K4 单独作为一条可比路径。
4. 20% 缓冲示例来自另一组工期推导，不能在基线未锁定时直接套用。

**处理要求：**先确定每项的 predecessor、successor 和 overlap，再按 DAG 计算最长路径。若暂时不能证明依赖，结论应为“工期 NOT_VERIFIED”，不要给出 7–14 天或 7.2–12 天的确定结论。

## 2. 批次 C：PR #60 的独立复核

### 2.1 WAL/SHM 缺失不能证明 checkpoint

PR #60 一方面声明本轮未执行 checkpoint，另一方面又将当前未发现 WAL/SHM 推断为“已完成 checkpoint/TRUNCATE”。文件系统快照只能支持“本次采集时指定路径未发现这些文件”，不能证明此前执行过哪种 SQLite 操作。

**建议统一表述：**
- `kbase.db-wal`：本次采集时 NOT_FOUND（限于报告所述路径与扫描范围）。
- `kbase.db-shm`：本次采集时 NOT_FOUND（限于报告所述路径与扫描范围）。
- checkpoint 历史/模式：NOT_OBSERVABLE。
- 不得推导 WAL 已合并、数据库已静止或可安全备份。

### 2.2 lsof 结论必须限制在检查范围

报告列出的 lsof 命令检查了指定主库路径和特定归档目录。即使输出为空，也只能支持“该命令在该主机、该时点、当前权限及指定路径范围内未观察到匹配句柄”。

它不能证明：
- 其他路径中的同一数据库副本未被打开；
- 其他主机或网络挂载卷不存在访问；
- 采集前后没有进程访问；
- 所有 SQLite/应用进程均未访问数据库。

将“所有数据库相关文件均未被任何进程打开”改为严格限定范围的观察结果。

### 2.3 SHA/mtime 变化必须保持 UNKNOWN

报告记录两次采集间主库 SHA-256 和 mtime 变化。该差异证明两次快照不相同，但不证明变化原因，也不证明第二次采集时数据库已静止。

建议结论：
- 两次采集之间文件内容/元数据发生变化：OBSERVED。
- 具体变更原因：UNKNOWN / NOT_OBSERVABLE。
- 变化发生后是否仍有其他进程、其他路径或其他主机访问：NOT_OBSERVABLE。
- 当前是否具备一致性备份条件：NOT_ESTABLISHED。

### 2.4 时间字段不能互相替代

报告记录 UTC 12:36:52、本地显示 20:36:52，并同时记录文件 mtime 17:41:11。mtime 是文件元数据，不是采集时间。报告应将采集时钟、显示时区、文件 mtime 分列，并保留系统时区配置未能直接读取这一限制。时间差只能说明两种显示值相差 8 小时，不能独立证明系统时区设置。

### 2.5 文件清单与 SHA256SUMS 范围不完整

报告元数据表中列出 `scam-corpus.db`、若干 lock 文件、空壳库以及备份 sidecar；SHA256SUMS 清单没有逐项覆盖所有这些对象。当前哈希文件只列出主库、两份备份、备份 2 的 SHM/WAL 和补遗文档。

需要建立一张逐项映射表，明确每个扫描对象属于：
- 纳入 SHA256SUMS；
- 因不存在而记录 NOT_FOUND；
- 因目录/权限/采集范围限制而 NOT_OBSERVABLE；
- 明确排除并给出排除理由。

不得将部分哈希清单描述为“全部文件完整性校验”。

### 2.6 备份 sidecar 的归属未证实

报告列出 `kbase.db.bak-20261115-0045-shm` 与 `...-wal`。文件名相似不能单独证明它们与备份主文件构成一个有效、同一时点的 SQLite 备份集合。需原始采集记录说明生成方式、关联关系及时间一致性；在此之前只作为独立发现的文件记录，不得推断备份可恢复。
