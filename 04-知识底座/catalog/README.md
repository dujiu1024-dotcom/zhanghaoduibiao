# A库资料目录（catalog）说明

状态：九类＋跨类，**68 项 / 355 条**，2026-11-14。只列条目，不抓取、不下载、不建存放位置。

本目录回答一个问题：**地图上每一项，书、论文、方法论、分享这四类资料各有什么，哪些还缺。**
它不回答"这些资料讲了什么"——那是入库与摘录阶段的事。

## 一、文件

| 文件 | 内容 |

| `catalog.csv` | 总表，355 条，11 列，UTF-8 BOM，Excel 可直接打开 |

## 二、11 列字段含义

| 列 | 含义 | 填写要求 |
| --- | --- | --- |
| 编号 | `类序号-条序号`，如 `05-17`；跨类用 `X-` | 自动生成，不手改 |
| 类 | 九类之一或"十、跨类项" | 与地图一致 |
| 项 | 该类下的具体项 | 一项只装这个角度，不跨项混装 |
| 资料名称 | 书名/篇名/框架名/报告名 | **经典列原版名**，有中译的在"依据"里注明 |
| 类型 | 书 / 论文 / 方法论 / 分享 / 法规 / 官方文档 | 六类，见 §四 |
| 作者或机构 | 作者、编者或发布机构 | 集体作品写机构，不写"佚名" |
| 年份 | 首版年或发布年；不明写"未获取" | 不是引用版本的年份 |
| 一句话它解决什么 | 落到**本账号的哪个动作** | 写不出动作的条目不该存在 |
| 真实性依据 | 凭什么说它存在 | 出版社／期刊卷期／课程名／报告发布方／署名页 |
| 优先级 | P0–P3 | P0＝不补会立刻出错；P3＝闲时补 |
| 状态 | 确认真实 / 待核 | 见 §五 |

## 三、"为什么归这一项"的判定

一条资料只能挂在**它主要解决的那个动作**下。同一本书不许挂三项充当三门知识；同一作者的不同书可以分挂（如 Goffman 的《日常生活中的自我呈现》在身份认同、《框架分析》在议程设置）。

若一条资料同时对上两格，挂**更靠前的动作**（先判断、再表达、再转化），另一格在"还缺什么"里注明"已有 X，可交叉用"。

## 四、四种资料类型（外加法规与官方文档）

- **书**：奠基作或权威教材。经典优先列原版（英文/德文/日文/法文/俄文原著），中译情况写在"真实性依据"里。例：`La Distinction` 列法文原著，注明英译 1984。
- **论文**：能查到期刊或会议来源的实证/综述。写得出期刊名与年份的才标"确认真实"；只有标题没有卷期的标"待核"。
- **方法论**：成型框架、模型、SOP。可以是行业通行框架（AARRR、BANT、MEDDIC、三档报价），不一定有出版物——但必须写清"谁在用、有没有原始文献"。
- **分享**：实战文章、公开课、案例复盘、行业报告、可查的博主/操盘手公开分享。
- **法规**：中国法律、行政法规、部门规章、司法解释。**单列，不塞进"书"**。
- **官方文档**：平台规则、帮助中心、官方课程。这类会改版，入库必须带抓取日期。
- **实时源（只用于 9.5）**：官方定价页、模型能力文档、公开评测榜、备案公示、本地实测记录。**"真实性依据"只填官方页面或实测记录，不填任何出版物**；每行标「本条不进买书清单」。价格与能力半年即过期，引用必须带抓取日期。
- **一手工程源（只用于 6.7–6.9）**：公司自己发表的论文、专利、技术博客与平台算法公示。类型栏写 `论文（一手）`／`专利（一手）`／`技术博客（一手）`／`官方文档（一手）`。**只能证明"这种机制被提出或公示"，不能反推流量数值**；从机制到流量之间没有桥。

## 五、「待核」怎么处理（重要）

**定义**：有明确存在线索，但没核到出版社、期刊卷期、作者署名页或官方页面。

**必须写线索**：每条待核的"真实性依据"里都要有一句"线索是……"。只写"待核"不写线索的，视为废条。

**不得引用**：待核条目不得进入内容脚本、方案、报价依据；引用前必须先核成"确认真实"。

**核的方式**（三步，按顺序）：
1. 出版社/期刊官网或 Crossref 查 DOI；
2. 作者主页、机构库、课程页；
3. 图书馆书目或 WorldCat 查版次。

**核完怎么改**：把状态改为"确认真实"，在"真实性依据"里补上确到的出版社/卷期/页面；核不到就删条，不留"大概有"。

**本表待核 49 条，占 14%。** 高优的 12 条已核过一轮（见 §七），现存 P0 待核是"本地实测记录"（须自己跑）与"抖音后台指标定义文本"（须登录后截图）。

## 六、收条规则（违反即整批退回）

1. 不凭记忆编书名、编论文标题、编作者。拿不准就标待核并写线索。
2. 每条必须能说出"为什么归这一项"，且这一项确实缺这个角度。
3. 每项 3–8 条，全表 250–400 条；**宁少不假**。现为每项 4–8 条、337 条。
4. **语言不限**：英文、日文、德文、法文、俄文、中文都算，中文不是必选项。判断某项"空"之前，必须先用非中文来源补过；中外各语种都找不到，才允许写空。
5. 已有英文经典只有中译的，列原版并注明译本情况。
6. 已在 `04-知识底座/knowledge/` 的本地资料不重复列；但某项**只有本地二手文档、没有原始来源**的，在分类 md 的"还缺什么"里单独标出。

## 八、项数口径（65 是怎么来的）

地图给的是"九类六十项"，只有类名与项数，没有项名；旧版文件 `00-战略与目标/道法术器/器/01-A库-我的知识库.md` 仍是七类四十三项。本表按裁定执行，项名由旧版条目迁移＋缺口补位得出，差异如下：

| 变化 | 结果 |
| --- | --- |
| 起点 | 60 项（九类 59＋跨类利他 1） |
| 字幕与信息密度从剪辑拆出（裁定 1） | ＋1 → 61 |
| 新增 4.9 个体老板与小额采购决策（裁定 2） | ＋1 → 62 |
| 新增 7.6 一人公司的协作与招人（裁定 3） | ＋1 → 63 |
| 新增 9.5 AI 模型能力与成本边界（只收实时源，裁定 3） | ＋1 → 64 |
| 新增 6.7／6.8／6.9 一手工程源三层（论文／专利／技术博客，裁定 4） | ＋3 → 67 |
| 新增跨类 心理阻抗与说服反噬（裁定 2） | ＋1 → 68 |

**与"60＋1＝61"的差 7 项**：原六十项里"字幕"被并进了剪辑项、"翻译方法"被放在了第五类，因此从剪辑拆出字幕会净增 1 项，不是 0；另有 4.9、7.6、9.5、心理阻抗与 6.7–6.9 三层共 6 次净增。本表未通过合并其他项来凑数。

**6.7–6.9 为什么单列成三项而不是并进 6.1／6.2**：一是"补三层"本身就是三层结构，混在一起就无法按层引用；二是 6.1、6.2 已各 6／4 条，并入后会超过"每项 3–8 条"的上限；三是把一手源与推断项物理分开，才能在文件开头写清"哪几条能当依据"。
