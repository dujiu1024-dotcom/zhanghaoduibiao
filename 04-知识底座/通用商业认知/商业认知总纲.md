# 商业认知总纲

版本：1.0｜阶段：3｜性质：通用认知底座

## 一、商业的基本解释

商业是围绕特定客户或利益相关方，识别问题与需求，组织资源创造价值，通过交易或其他可持续机制传递价值并获取回报的系统。

完整链路：

`需求/问题 → 价值识别 → 价值设计 → 资源组织 → 价值交付 → 交易/变现 → 收入与现金回收 → 再投资/改进`

任何商业判断至少回答：
1. 谁是客户/受益者/付费者/决策者？
2. 客户正在完成什么任务、解决什么问题？
3. 当前替代方案是什么，客户为何改变？
4. 我方提供的价值是否可感知、可验证、可交付？
5. 谁为价值付费，如何定价、交易和回款？
6. 交付成本、获客成本、服务成本和风险如何？
7. 优势能否持续，竞争者能否复制？
8. 现金流、组织和供应能力能否支撑规模化？

## 二、商业系统的九个基本原理

### 1. 价值创造
客户价值来自问题重要性、解决效果、体验改善、风险降低或机会增加。价值必须以客户行为、支付、续约、使用或其他证据验证，不能只以企业自我描述判断。

### 2. 价值传递
产品、渠道、销售、交付、服务和客户成功共同构成价值传递系统。任何环节的摩擦都会降低转化或交付结果。

### 3. 价值获取
创造价值不等于获得利润。价值获取依赖定价权、交易结构、成本结构、议价能力、产权/合同安排和现金回收。

### 4. 稀缺与取舍
资源、注意力、时间、资本和组织能力有限。战略本质上包含选择与放弃，不能把所有机会都列为优先事项。

### 5. 供需与价格
价格受供需、替代性、支付意愿、议价结构、信息差和交易成本影响。标价不等于成交价，收入不等于回款。

### 6. 激励与代理
个人和组织会响应其激励、考核和信息结构。流程失效不一定是态度问题，也可能是目标冲突、权责不清或激励扭曲。

### 7. 竞争与反应
竞争不仅是当前对手，也包括替代方案、潜在进入者、上下游议价方和客户自建。策略会改变对手行为，不能把竞争环境当静态背景。

### 8. 风险与不确定性
风险是结果分布及损失暴露；不确定性是概率或因果关系本身不清楚。需区分可量化风险、模型风险和未知。

### 9. 现金与时间
利润、现金、资产和增长速度是不同维度。增长可能消耗现金；账面盈利也可能因应收、库存、资本开支和融资条件而陷入流动性危机。

## 三、商业分析的统一对象模型

| 对象 | 关键字段 |
|---|---|
| 目标 | 目标值、期限、优先级、约束、不可接受结果 |
| 客户/利益相关方 | 角色、任务、痛点、支付者、决策权、替代方案 |
| 产品/价值主张 | 功能、效果、差异、证据、交付承诺 |
| 市场 | 范围、细分、规模、增长、地域、监管、周期 |
| 竞争者/替代品 | 目标客户、能力、成本、价格、渠道、反应 |
| 资源 | 资金、人才、技术、产能、渠道、时间 |
| 经营活动 | 获客、销售、交付、服务、采购、生产、回款 |
| 财务结果 | 收入、成本、利润、现金流、资产负债 |
| 风险 | 事件、原因、影响、概率/暴露、控制、责任人 |
| 决策 | 选项、证据、假设、收益、代价、风险、审批和退出条件 |

## 四、通用分析纪律

- 先定义决策问题，不从熟悉的模型开始。
- 先识别利益相关方，再确定客户和付费者是否为同一主体。
- 先建立事实和数据口径，再进行归因。
- 先识别替代方案，再判断差异化。
- 先验证客户行为，再相信访谈中的态度表达。
- 同时看收入、利润、现金、风险和组织承载力。
- 任何预测写明假设、区间、敏感变量和失效条件。
- 结论必须说明什么证据会推翻它。

## 五、事实与判断六分法

| 类型 | 定义 | 表达要求 |
|---|---|---|
| 事实 | 可从来源核验的记录 | 来源、时间、口径、范围 |
| 推断 | 从事实推出的解释 | 推理链、前提、置信度 |
| 假设 | 尚未证实的前提 | 验证方法、失败条件 |
| 未知 | 当前信息不足 | 不填空，列出最小取证动作 |
| 偏好 | 决策者价值取向 | 标明主体，可由其修正 |
| 建议 | 可执行的行动主张 | 依据、收益、代价、风险、负责人 |

## 六、分析输出标准

每份重要商业分析至少包含：
1. 执行摘要与待决问题；
2. 目标、边界和成功标准；
3. 已知事实与来源；
4. 关键未知、假设和证据缺口；
5. 相关利益方和环境；
6. 结构化分析及关键变量；
7. 至少两个可行选项（低风险简单事项可说明为何无需比较）；
8. 推荐方案及不选其他方案的理由；
9. 风险、反证、敏感变量和退出条件；
10. 行动计划、指标、负责人和复盘节点。

## 七、适用边界

本总纲是通用认知框架，不替代行业法规、专业会计/法律意见、技术尽调或真实客户验证。遇到高风险专业事项，必须明确能力边界并引入合格专业人员。
