# A 库检索验收

这是操盘手自己用的检索验收工具：**固定题库 + 一条命令跑分 + 直接判通过/不通过**。以后每次改检索（改 rag.py、改阈值、换嵌入模型、重新切段、补料入库）都必须先跑这套，再说话。

- 只读：脚本不写 `kbase.db`，不改库内任何数据。
- 可重复：题库固定、参数固定（`-k 10` + 日常默认阈值），结果可与上一次报告逐项对比。
- 可定位：每题都带 gold 文档与段号，跑分只回答一件事——**该找到的那一段，找没找到、排第几**。

## 一、目录

```
验收/
├── README.md                 # 本文件
├── check_recall.py           # 跑分脚本
├── 题库/
│   ├── 01-判断与决策支持.csv
│   ├── 02-知识底座维护.csv
│   ├── ...
│   └── 12-复盘与归因.csv
└── 报告-YYYYMMDD-HHMM.md     # 每次跑分自动生成
```

题库按 12 项职责分组，每组 20 题，共 240 题（235 道计分 + 5 道已知无料），已全部补齐。

## 二、怎么跑

```bash
cd 04-知识底座

# 跑全部组，终端出分并写报告
./rag/.venv/bin/python 验收/check_recall.py

# 只跑一组 / 几组
./rag/.venv/bin/python 验收/check_recall.py --group 06
./rag/.venv/bin/python 验收/check_recall.py --group 06 --group 09

# 只看分，不写报告
./rag/.venv/bin/python 验收/check_recall.py --no-report

# 指定报告路径
./rag/.venv/bin/python 验收/check_recall.py --report 验收/报告-改阈值后.md

# 深诊断（名次分档 / 四分类 / 候选上界 / 段长分布）
./rag/.venv/bin/python 验收/check_recall.py --deep --no-report
```

`--deep` 在每题上多跑两次检索（`-k 50`、`-k 200`），并额外产出 `名次分布-YYYYMMDD-HHMM.md` 与 `名次明细-YYYYMMDD-HHMM.csv`。它回答的问题只有一个：**gold 是根本没进候选，还是进了候选但排位靠后**。不加 `--deep` 时行为和以前一致，只跑 `-k 10`。

检索入口固定为日常用法：

```bash
rag/.venv/bin/python rag/rag.py search "<问题>" -k 10 --json
```

脚本默认取 `--json` 的 top-10；top-5 是前 5 条。耗时包含子进程启动与 embedding 请求，只用于横向对比，不是纯检索耗时。

退出码：`0` = 五项通过线全过；`1` = 不通过（报告里会列出未达标项）。

## 三、字段与判定口径

题库每行 9 列：

| 列 | 说明 |
| --- | --- |
| 题号 | `职责编号-序号`，如 `06-013`；全局唯一 |
| 问题原文 | 人的自然问法，不写成关键词堆 |
| gold路径 | 相对 `04-知识底座/knowledge/` 的路径，如 `methodology/03-违规红线.md`；法条写 `sources/fulltext/law/...` |
| gold段号 | `§n` 或 `第X条`；必须是库里真实存在的段号 |
| 判定标准 | 以 `[段级]` 或 `[文档级]` 开头，写明命中什么算对 |
| 期望能否引原文 | `能` / `只能转述` / `不适用`（无料题） |
| 期望 | `命中` / `无料` |
| 无料归因 | 已知无料题、跑分未召回题必填：`缺资料` / `需实测` / `待查` |
| 补料建议 | 一句话：补什么、去哪补，或排进哪个业务动作 |

匹配规则：

- `[段级]`：路径相同，且命中段号等于 gold 段号（允许 `§3.2` 命中 `§3`）。
- `[文档级]`：路径相同即可，用于全篇只有一段或问题不指向某一节的文档。
- 路径归一：`sources/fulltext/knowledge/methodology__X.txt` 是自撰笔记副本，归一到 `methodology/X.md`，避免同一段内容因路径不同被判成两个文档。
- 载入题库时先校验 gold：路径不存在、段号不存在，直接拒绝跑分（规则：gold 指不到真实文档/段号的题不许出）。

指标：

| 指标 | 定义 |
| --- | --- |
| Recall@5 / Recall@10 | 非无料题中，gold 出现在前 5 / 前 10 的比例 |
| MRR | 非无料题中，gold 排名倒数的平均值（未进 top-10 记 0） |
| 原文命中率（分母=gold为原文的题） | gold 指向 `sources/fulltext/`（书/法规/论文/官方文档）的题里，top-5 至少出现 1 条「原文 + 可引用」命中的比例。只拿笔记当 gold 的题永远命中不了原文，所以不放进分母 |
| gold原文占比 | 全部计分题里，gold 为原文的题占多少。用来告诉读者原文命中率这条线覆盖了题库的多大比例 |
| 无料题数 | 标 `期望=无料` 的题数，**不计入 Recall/MRR 分母** |
| 无料拒答 | 无料题中检索正确返回 `no_answer` 的题数 |
| 平均耗时 | 全部题的平均墙钟耗时（含子进程启动） |

来源构成：按 `source_path` 前缀判，`原文` = `knowledge/sources/fulltext/`（不含 `fulltext/knowledge/` 自撰笔记副本）；`经验` = `experience/`；其余为 `笔记`（methodology、accounts、topics、sources/secondhand、books 索引等）。当前 `experience/` 未入检索库，所以「经验」一列通常为 0。

### 深诊断指标（`--deep`）

| 指标 | 定义 |
| --- | --- |
| 四分类 | 每题归一类：`命中`（融合前 5）/ `在某路候选，融合后掉出前5`（融合结果有但名次 >5，含被 per_doc 截断、只在单路候选）/ `进前10但被跨语言规则顶出前5`（融合进前 10 且该条被标 `cross`，`fuse()` 把 cross 统一排到最后）/ `不在任何一路候选`（融合、字面单路、标签单路都找不到） |
| 候选上界 Recall@50 | `-k 50` 时 gold 是否出现在融合候选里。这是重排能触及的天花板 |
| 排序损失 | 候选上界 Recall@50 − 实测 Recall@5。差值全部来自排序，不是召回 |
| 名次分档 | 融合候选里 gold 的名次：1 / 2-5 / 6-10 / 11-20 / 21-50 / 不在前50 |
| 每路原始名次 | 命中记录里的 `channels` 字段，记 literal / tag / vector 三路各自的名次。gold 不在融合候选里时补跑 `--mode literal` / `--mode tag` 确认；`--mode vector` 目前返回空（`search()` 只在 hybrid 下取向量），所以向量单路无法单独探测 |
| gold 段长 | gold 段原文的字数，分 <200 / 200-400 / 400-800 / 800-1500 / >1500 五档，另给中位数 |
| 段内位置 | 【推算】问句字组在 gold 段里首次出现的位置，粗判段首（<33%）/ 段中 / 段尾。只用于查「切段太长」，不是语义标注 |
| 四格 | 问句语言 → gold 文档语言（中→中 / 中→英 / 英→中 / 英→英），各格题数与「gold 进了候选」的占比 |

深诊断的硬约束（读数字前必看）：

- **k 最大只能到 51**。检索器内部先把向量池放大（`pool = max(k*10, 50)`）再乘 8 取 KNN，sqlite-vec 的 KNN `LIMIT` 上限是 4096，所以 `k=200` 会直接报 `k value in knn query too large`。不改 `rag.py` 就探不到 50 名以后，因此最后一档是「不在前50」，不区分 `>50` 与完全不在候选。
- **触发跨语言扩写的题会把内部 k 翻倍**（`search(conn, eq, args.k*2, ...)`），`k=50` 时撞同一个上限。这类题（当前题库 235 道计分题里有 45 道）自动改用 `--no-xling` 跑，名次表里会标「本次关闭跨语言扩写后测得」。
- 每份报告头部都记 `rag.py` / `terms.csv` / `synonyms.json` 的 mtime 与 sha1 前 8 位。另一条线在改检索，**两版报告只在这三个文件一致时才可比**。

## 四、通过线（照此判定，不靠人看数字）

报告顶部直接给 `验收结论：通过` 或 `验收结论：不通过`，并列出未达标项。判定逻辑写死在 `check_recall.py` 的 `verdict()`：

1. **空结果硬失败**：除标「已知无料」的题以外，任何一题返回空结果（`no_answer`、零候选）即判不通过。空多半是被相关性闸门静默拦下，不是库里没料；这种情况以前被误判成「没料」，所以单独设成硬失败。低置信候选不算空（有候选就必须判命中/未命中，不能判「没料」）。
2. **总 Recall@5 ≥ 70%**。
3. **原文命中率（分母=gold为原文的题）≥ 60%**：防止答案全靠二手笔记，必须让「库里确实有原文」的题有足够比例在前五看到可引原文。
4. **每组 Recall@5 ≥ 50%**（仅对满 20 题的组生效）：不许靠个别高分组抬总分。
5. **已知无料题不计分，但每道必须有归因与补料建议**；缺任一项即不通过。

组未满 20 题时，报告写「本组仅 N 题，判定暂不作数」，该组不参与规则 4 的判定；总分仍照算，但只作基线参考，不作为最终验收。

通过线的理由：70% 意味着 10 个真实问题最多错 3 个；组线 50% 防偏科；原文 60% 防止「能搜到笔记但引不了原文」；空结果单列，是因为空结果分不清「没料」还是「门槛拦了」，必须先修检索再谈缺料。

原文命中率的分母为什么只算 gold 为原文的题：12 个重点细类里只有 4 类有真对题原文、4 类部分有、4 类只有本库笔记。把「永远不可能命中原文」的笔记题放进分母，这条线数学上就过不了，等于用一条不可能过的线假装严格。现在分母只留 gold 是原文的题，同时单列 `gold原文占比`，读的人能一眼看出这条线覆盖了多少题、剩下多少题只能靠笔记。

## 五、未召回与「无料」的处理规则（硬规则）

**跑分未召回，不许直接判「库里没料」。** 先分清两种情况：

- **有候选、只是 gold 没进 top10**：这是排序问题，不是缺料。记入「未通过项明细」的排序问题，不进补料清单；处理动作是改检索/改排序，不是买料。
- **零候选（真空）**：才按第三类「待查」回看一遍：换同义说法、拆成单词、去掉「怎么/为什么/到底」再问一遍，必要时直接用 `rag.py search "<换过的问法>" -k 10` 手工复测。换词后仍无命中，才可以把该题改为：

- `缺资料`：世上公开可得的材料（书/论文/官方文档/案例），我们没采。补料建议里写清缺什么类型、去哪采、可自动化还是需人工。
- `需实测`：只有真跑业务才能得到（话术、成交、验收口径、低价单转化等）。补料建议里写清需要哪个真实动作、产出后回填到哪。
- `待查`：库里可能其实有，是检索没捞到。逐题写清换了哪些问法、复测结果是「有料但难捞」还是「确实没有」。

理由：法条那次就是有料却没捞到，直接判缺料会白买一批不该买的东西。**先复测，再定性。**

报告最后一节「补料清单」按三归因分组；未召回题若题库里还没填归因，脚本默认归到 `待查`，并给出换词建议，等人工复测后回填题库。
