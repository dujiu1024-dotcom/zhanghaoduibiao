# Gold 名次与四分类诊断 — 2026-11-15 20:25

- 检索侧快照：rag.py 11-15 17:38/8f1669a8；terms.csv 11-15 16:33/85b62cef；synonyms.json 11-15 16:27/6237bf70。另一条线正在改检索，本报告只对应上面这个版本，之后改了什么都要重跑才可比。
- 口径：每题跑两次 `rag.py search "<问题>" -k 10 / -k 50 --json`。实测 Recall@5 取 `-k 10`（与验收基线同口径）；候选上界与名次分档都取 `-k 50`。
- **名次上限说明**：检索器内部把向量池放大 10 倍（`pool = max(k*10, 50)`）再乘 8 取 KNN，sqlite-vec 的 KNN LIMIT 上限是 4096，所以 k 最大只能到 51，k=200 会直接报 `k value in knn query too large`。不改 rag.py 就只能探到 50 名这一层，所以最后一档是「不在前50」，不再区分 >50 与完全不在候选。
- 每路原始名次：取命中记录里的 `channels` 字段（literal / tag / vector 三路各自的名次）。gold 不在融合候选里时，再单独跑 `--mode literal` / `--mode tag` 确认是否在某路候选中；`--mode vector` 目前返回空（`search()` 只在 hybrid 下取向量），所以向量单路无法单独探测。
- 四分类：命中＝融合前 5；在某路候选但掉出前 5＝融合结果里能找到但名次 >5（含被 per_doc 截断、或只在单路候选中）；被跨语言顶出前 5＝融合进前 10 且该条被标 `cross`（`fuse()` 把 cross 统一排到最后）；不在任何一路候选＝融合、字面单路、标签单路三处都找不到。
- 段内位置为【推算】：用问句字组在 gold 段里首次出现的位置粗判，不是语义标注。
