# RAG 治理与评测方案

## 1. 当前风险基线

仓库现有 RAG 代码采用 SQLite、中文字面倒排、人工标签和本地向量通道。当前 `04-知识底座/rag/rag.py` 的 `SIM_FLOOR` 代码默认值为 0.60；同仓库 `04-知识底座/rag/README.md` 的旧查询示例仍显示“成答下限 0.66”。这两处名称/语义并不完全相同，不能直接当作同一参数比较；该 README 示例至少属于需要复测更新的历史输出，实际运行时还需同时记录 `SIM_FLOOR`、`ANSWER_MIN_COVERAGE`、`SHORT_RELAX`、`ENTITY_GATE` 等配置。

本方案沿用的历史记录还提及有答案 20 条/无答案 12 条、命中 15/20、负集硬答 5/12，以及更早的 240 题 Recall@5 56.2%、60 条负集硬答 44 条。但本轮未定位到这些数字对应的原始题集版本、gold 标注和完整评测报告，因此全部标记为**未核验历史记录**，不得作为当前基线或通过成绩。必须先找回原始数据与报告，核对题目是否重复、口径是否一致，再决定是否保留作历史对照。

**结论：** 当前没有可作为正式基线的统一评测结果。统一评测前，RAG 仅作为定位线索，重要结论回到原文核验。

## 2. RAG 链路与评测集结构

评测必须分层定位错误，不把所有失败归结为“召回差”：
1. 查询理解/改写：是否正确识别实体、时间、业务对象和答案类型。
2. 候选召回：是否召回包含 gold 来源的候选文档/段落。
3. 融合与重排：相关证据是否排在足够靠前的位置，是否被相似干扰挤出。
4. 答案生成：回答是否严格受检索证据支持，是否引入未提供事实。
5. 引用生成：来源、段落定位是否真实且足以支持对应主张。
6. 可回答性判断与拒答：库内无答案或证据不足时，是否明确拒答并说明缺口。



- 正向集：有明确可支持来源的查询，标注 gold source、gold locator、能力域和难度。
- 负向集：库内确实没有答案的问题，标注为什么无答案、相近干扰源和期望拒答。
- 对抗集：关键词相似但语义不同、过期规则、相互矛盾来源、跨语言实体、长短问句。
- 独立保留集：不参与调参，不公开给调参流程；只在候选版本冻结后评测。
- 领域集：战略、竞争、营销、经营、财务、组织、商业模式、风险和研究。

每条题目字段：question_id、query、expected_answerable、gold_source_ids、gold_locators、domain、difficulty、confounders、expected_behavior、dataset_version。

## 3. 指标

| 指标 | 定义 | 目标使用 |
|---|---|---|
| Recall@k | 前 k 命中至少一个 gold 来源的比例 | 衡量召回 |
| MRR / nDCG | gold 结果排序质量 | 衡量排序 |
| Precision@k | 前 k 结果中相关结果比例 | 衡量噪声 |
| Answerability precision | 系统判可回答的题中真实可回答比例 | 控制硬答 |
| Answerability recall | 可回答题中被系统正确判为可回答的比例 | 防止过度拒答 |
| Answer faithfulness | 生成答案中的事实主张受检索证据支持的比例 | 控制幻觉/越证据回答 |
| Negative abstention rate | 负集正确拒答比例 | 控制无答案 |
| Citation accuracy | 引用来源/定位准确比例 | 控制可追溯 |
| Stale-hit rate | 已过期资料进入有效答案的比例 | 控制时效 |
| Sensitive leakage | 不应输出的敏感资料泄露次数 | 安全指标 |

不以单一 Recall 指标代表系统质量；必须联合考察拒答、引用准确和过期命中。

## 4. 评测纪律

1. 每次评测绑定 Git commit、脚本指纹、模型名称/版本、参数、知识库快照、题集版本和时间。
2. 调参集与独立保留集分离。
3. 先冻结基线，再调整召回、排序、实体闸门和拒答阈值。
4. 不得删除困难负例以改善分数；题目变更必须有版本差异。
5. 评测报告包含逐题错误分析，不只给总体百分比。
6. 重大改动必须回归所有受影响能力域。
7. 只有在独立保留集达到项目门槛且无关键安全缺陷时，才可标记 C5。

## 6. 检索使用边界

- 召回结果是候选证据，不是答案。
- 标签命中只表示主题相关，不等于原文直接支持。
- 任何重要引用必须回到原始文件或网页核验。
- 无答案时允许拒答并提出外部取证。
- 个人知识层 E 默认不参与通用任务检索。
- B 层动态情报必须检查有效期和来源日期。
