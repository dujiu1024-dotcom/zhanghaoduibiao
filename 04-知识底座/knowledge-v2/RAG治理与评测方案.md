# RAG 治理与评测方案

## 1. 当前风险基线

仓库现有 RAG 代码采用 SQLite、中文字面倒排、人工标签和本地向量通道。按当前 `04-知识底座/rag/rag.py` 源码默认值：`SIM_FLOOR=0.66`、`ANSWER_MIN_COVERAGE=0.50`、`OOV_FLOOR=0.50`、`COVERAGE_FLOOR=0.32`；`SHORT_RELAX`、`ENTITY_GATE`、`RAG_STRICT` 默认关闭。`SIM_FLOOR` 是向量相似度下限，`ANSWER_MIN_COVERAGE` 是字面单独成答的覆盖率下限，`COVERAGE_FLOOR` 是字面候选进入融合的下限，三者不可混称。`RAG_SIM_FLOOR`、`RAG_ANSWER_MIN_COVERAGE` 等环境变量可覆盖源码默认值；因此这些数字不代表用户本机实际生效值，真机评测必须记录运行环境的最终配置。

本方案沿用的历史记录还提及有答案 20 条/无答案 12 条、命中 15/20、负集硬答 5/12，以及更早的 240 题 Recall@5 56.2%、60 条负集硬答 44 条。但本轮未定位到这些数字对应的原始题集版本、gold 标注和完整评测报告，因此全部标记为**未核验历史记录**，不得作为当前基线或通过成绩。必须先找回原始数据与报告，核对题目是否重复、口径是否一致，再决定是否保留作历史对照。

**结论：** 当前没有可作为正式基线的统一评测结果。统一评测前，RAG 仅作为定位线索，重要结论回到原文核验。

## 2. RAG 链路与评测集结构

评测必须分层定位错误，不把所有失败归结为“召回差”：
1. 查询理解/改写：是否正确识别实体、时间、业务对象和答案类型。
2. 候选召回：是否召回包含 gold 来源的候选文档/段落。
3. 融合与重排：相关证据是否排在足够靠前的位置，是否被相似干扰挤出。
4. 答案生成：回答是否严格受检索证据支持，是否引入未提供事实。
5. 引用生成：来源、段落定位是否真实且足以支持对应主张。
6. 可回答性判断与拒答：库内无答案或证据不足时，是否明确拒答并说明缺口。

- 正向集：有明确可支持来源的查询，标注 gold source、gold locator、能力域和难度。
- 负向集：库内确实没有答案的问题，标注为什么无答案、相近干扰源和期望拒答。
- 对抗集：关键词相似但语义不同、过期规则、相互矛盾来源、跨语言实体、长短问句。
- 独立保留集：不参与调参，不公开给调参流程；只在候选版本冻结后评测。
- 领域集：战略、竞争、营销、经营、财务、组织、商业模式、风险和研究。

每条题目字段：question_id、query、expected_answerable、gold_source_ids、gold_locators、domain、difficulty、confounders、expected_behavior、dataset_version。

## 3. 指标定义与计算口径

所有指标按题目逐条计算，再按题集版本、领域、难度和答案类型分层汇总；同时报告分子、分母、样本量和置信区间。不得只给总体百分比。

| 指标 | 计算口径 | 衡量环节 |
|---|---|---|
| Recall@k | 对每题，前 k 个候选中命中至少一个 gold source/locator 记 1；总命中题数 ÷ 有答案题数 | 候选召回 |
| Precision@k | 前 k 个候选中相关候选数 ÷ 返回候选总数，再对题目宏平均；无候选题记 0 并单列 | 候选噪声 |
| MRR | 每题第一个 gold 候选排名的倒数；未命中记 0，跨题求平均 | 首个相关结果排序 |
| nDCG@k | 按人工相关性等级计算 DCG@k / IDCG@k，再跨题宏平均；等级定义随题集版本冻结 | 整体排序质量 |
| Answerability precision | 被系统判为可回答且实际可回答的题数 ÷ 系统判可回答题数 | 防止无证据硬答 |
| Answerability recall | 被系统判为可回答的真实可回答题数 ÷ 真实可回答题数 | 防止过度拒答 |
| Answer faithfulness | 有检索证据的回答中，得到证据支持的事实主张数 ÷ 回答事实主张总数；人工标注或经校验评审 | 生成忠实度 |
| Negative abstention rate | 负向集上正确拒答题数 ÷ 负向题总数 | 无答案拒答 |
| Citation accuracy | 引用来源与定位真实且能支持对应主张的引用数 ÷ 被核验引用总数；同时报告引用覆盖率 | 引用质量 |
| Stale-hit rate | 过期/失效资料被作为当前有效依据的题数 ÷ 含过期干扰的评测题数 | 时效治理 |
| Sensitive leakage | 未授权敏感信息输出事件数；按严重度记录，关键泄露零容忍 | 权限安全 |

`Recall@k` 与 `Precision@k` 必须在固定 k 和固定候选去重规则下比较；MRR/nDCG 必须冻结相关性标注口径。答案忠实度、引用正确性和敏感泄露不得只依赖模型自评。

## 4. 评测纪律

1. 每次评测绑定 Git commit、脚本指纹、模型名称/版本、参数、知识库快照、题集版本和时间。
2. 调参集与独立保留集分离。
3. 先冻结基线，再调整召回、排序、实体闸门和拒答阈值。
4. 不得删除困难负例以改善分数；题目变更必须有版本差异。
5. 评测报告包含逐题错误分析，不只给总体百分比。
6. 重大改动必须回归所有受影响能力域。
7. 只有在独立保留集达到项目门槛且无关键安全缺陷时，才可标记 C5。
8. 每次报告必须说明阈值参数名称与实际运行值；不得把相似度阈值、字面覆盖率阈值和答案拒答门槛混称为一个“成答阈值”。
9. 正向、负向、对抗和保留集必须有不同用途与访问控制；保留集不得进入调参提示、索引调试或规则优化反馈。

## 6. 检索使用边界

- 召回结果是候选证据，不是答案。
- 标签命中只表示主题相关，不等于原文直接支持。
- 任何重要引用必须回到原始文件或网页核验。
- 无答案时允许拒答并提出外部取证。
- 个人知识层 E 默认不参与通用任务检索。
- B 层动态情报必须检查有效期和来源日期。
