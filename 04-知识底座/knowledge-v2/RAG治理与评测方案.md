# RAG 治理与评测方案

## 1. 当前风险基线

仓库现有 RAG 使用 SQLite、中文字面倒排、人工标签和本地向量通道。现存评测报告记录的历史样本为有答案 20 条、无答案 12 条，混合检索命中 15/20、负集硬答 5/12；更早的用户视图又记录 240 题 Recall@5 56.2% 和 60 条负集硬答 44 条。当前 `rag.py` 中 SIM_FLOOR 默认值为 0.60，而 README/历史报告出现 0.66。不同数据集、代码版本和参数不可混为同一指标。

**结论：** 这些是历史风险信号，不是当前版本的通过成绩。统一评测前，RAG 仅作为定位线索，重要结论回到原文核验。

## 2. 评测集结构

- 正向集：有明确可支持来源的查询，标注 gold source、gold locator、能力域和难度。
- 负向集：库内确实没有答案的问题，标注为什么无答案、相近干扰源和期望拒答。
- 对抗集：关键词相似但语义不同、过期规则、相互矛盾来源、跨语言实体、长短问句。
- 独立保留集：不参与调参，不公开给调参流程；只在候选版本冻结后评测。
- 领域集：战略、竞争、营销、经营、财务、组织、商业模式、风险和研究。

每条题目字段：question_id、query、expected_answerable、gold_source_ids、gold_locators、domain、difficulty、confounders、expected_behavior、dataset_version。

## 3. 指标

| 指标 | 定义 | 目标使用 |
|---|---|---|
| Recall@k | 前 k 命中至少一个 gold 来源的比例 | 衡量召回 |
| MRR / nDCG | gold 结果排序质量 | 衡量排序 |
| Precision@k | 前 k 结果中相关结果比例 | 衡量噪声 |
| Answerability precision | 系统判可回答的题中真实可回答比例 | 控制硬答 |
| Negative abstention rate | 负集正确拒答比例 | 控制无答案 |
| Citation accuracy | 引用来源/定位准确比例 | 控制可追溯 |
| Stale-hit rate | 已过期资料进入有效答案的比例 | 控制时效 |
| Sensitive leakage | 不应输出的敏感资料泄露次数 | 安全指标 |

不以单一 Recall 指标代表系统质量；必须联合考察拒答、引用准确和过期命中。

## 4. 评测纪律

1. 每次评测绑定 Git commit、脚本指纹、模型名称/版本、参数、知识库快照、题集版本和时间。
2. 调参集与独立保留集分离。
3. 先冻结基线，再调整召回、排序、实体闸门和拒答阈值。
4. 不得删除困难负例以改善分数；题目变更必须有版本差异。
5. 评测报告包含逐题错误分析，不只给总体百分比。
6. 重大改动必须回归所有受影响能力域。
7. 只有在独立保留集达到项目门槛且无关键安全缺陷时，才可标记 C5。

## 6. 检索使用边界

- 召回结果是候选证据，不是答案。
- 标签命中只表示主题相关，不等于原文直接支持。
- 任何重要引用必须回到原始文件或网页核验。
- 无答案时允许拒答并提出外部取证。
- 个人知识层 E 默认不参与通用任务检索。
- B 层动态情报必须检查有效期和来源日期。
