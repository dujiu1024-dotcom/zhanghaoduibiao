# 知识元数据规范

## 1. 必填字段

| 字段 | 类型 | 说明 |
|---|---|---|
| knowledge_id | string | 稳定唯一 ID，不随标题修改 |
| title | string | 资料标题 |
| layer | enum | A/B/C/D/E |
| domain | string | 一级领域 |
| subdomain | string | 二级领域 |
| knowledge_type | enum | principle/method/fact/data/case/experience/regulation/official_doc/opinion |
| source_type | enum | primary/official/academic/industry/internal/interview/experiment/secondary/user_provided |
| source_name | string | 作者、机构或系统；未知明确写 unknown |
| source_uri | string | URL 或仓库相对路径 |
| locator | string | 页码、章节、段落、表格、时间戳 |
| published_at | date/null | 发布日期，未知留空 |
| collected_at | datetime | 实际采集时间 |
| updated_at | datetime | 最近更新 |
| rights_status | enum | open_license/public_domain/official_text/permission/unknown/all_rights_reserved |
| license_name | string/null | 许可名称或法律依据；未知留空 |
| license_uri | string/null | 许可文本或官方权利说明链接 |
| rights_evidence | string | 授权判断依据、许可截图/合同路径或官方说明定位；未知须明确写 unknown |
| rights_reviewed_at | datetime/null | 最近一次授权审查时间 |
| rights_reviewer | string/null | 授权审查责任人/角色 |
| quote_policy | enum | quote/summary_only/no_use |
| quality_level | enum | verified/traceable/secondary/unverified/obsolete |
| confidence | enum | high/medium/low/unknown |
| verification_status | enum | unverified/partially_verified/verified/contradicted/not_applicable |
| verified_at | datetime/null | 最近一次内容核验时间；未核验留空 |
| verifier | string/null | 核验责任人/角色 |
| verification_method | enum | source_check/cross_source_check/data_reproduction/expert_review/user_confirmation/none |
| verification_evidence | string | 支持核验状态的来源定位、复算记录或审查记录；未知写 unknown |
| scope | object | 行业、地域、客户群、业务阶段、时间范围 |
| valid_from | date/null | 生效时间 |
| valid_until | date/null | 失效时间/复核时间 |
| sensitivity | enum | public/internal/confidential/personal |
| owner | string | 维护责任人/角色 |
| status | enum | draft/active/review_due/superseded/archived/rejected |
| sha256 | string | 原始文件指纹，变更时更新 |
| related_ids | array | 关联知识、案例、主张 |

**状态字段不可混用：** `verification_status` 描述内容主张是否经过核验；`status` 描述知识条目在治理流程中的生命周期。条目可以是 `active + partially_verified`，但不得因进入 active 就自动视为 verified。缺少证据时不得把 verification_status 填为 verified。

## 2. 来源质量规则

- 官方/法规/原始业务系统数据优先，但官方来源也需检查发布时间、适用范围和是否更新。
- 学术论文需记录作者、期刊/会议、年份、DOI/URL、研究对象和局限。
- 行业报告需识别发布机构、商业利益、样本方法和数据口径。
- 访谈需记录对象角色、时间、样本数、问题提纲和授权；访谈观点不是事实的普遍代表。
- 内部数据需记录来源系统、导出时间、字段定义、脱敏方式和访问权限。
- 二手转述可作为研究线索，不能冒充一手来源。

## 3. 引用与版权

按具体许可和适用法律确定引用范围：`quote` 仅用于已核实允许引用原文的材料；`summary_only` 用于授权未知或保留所有权利、但可在合法范围内摘要/转述的材料；`no_use` 用于授权不允许使用、授权撤回或无法确认可合法处理的材料。授权未知或保留所有权利的材料不得输出长段原文；法规和官方文本按其法律属性处理。不得将内部历史“可转述”规则误当法律意见。每份资料保留许可名称、许可链接、权利判断证据、审查时间和责任人。

## 4. 过期与冲突

- 动态数据必须设复核周期：政策/平台规则按变更频率；价格/产品能力按月或事件触发；理论方法按年度或发现反例时复核。
- 同一主张冲突时保留多个版本，记录适用时间、口径和来源质量；不静默覆盖。
- 被替代资料标记 superseded/obsolete，并记录替代关系。
- 资料没有明确有效期时，不得默认永久有效。

## 5. 切段元数据

每个检索段必须继承：knowledge_id、layer、domain、source_id、locator、quality_level、rights_status、quote_policy、scope、valid_until、sensitivity、verification_status 和原文指纹。引用输出至少给原文件路径和段落定位。
