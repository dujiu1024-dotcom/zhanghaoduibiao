# 通用商业知识体系 V2

状态：治理方案已建立；历史知识未批量搬迁；RAG 运行指标待统一复测。

## 目标

将旧有以个人 IP/账号运营为中心的知识资产，逐步治理为支持通用商业操盘的 A-E 分层知识体系。迁移以“先分类、再验证、后搬迁”为原则，不做无差别复制，不删除原始材料。

## 分层

- A 通用商业认知：跨行业原理、战略、竞争、营销、经营、财务、组织、决策方法。
- B 行业与市场情报：行业结构、政策、市场规模、客户行为、技术趋势、竞争情报。
- C 专业领域知识：职能/专业/业务模式知识；个人 IP 与内容运营归入 C 的一个专业子域。
- D 具体业务项目知识：客户、产品、项目、投标、交付、运营和复盘材料。
- E 个人专属知识：个人经历、偏好、能力、私有数据和私人案例。

```text
│   └── evaluation/
├── knowledge/                # 旧知识原件，未完成审计前保持原位
├── rag/                      # 旧 RAG 引擎，治理后再决定迁移/改造
└── catalog/                  # 旧资料目录，按映射表保留
```

## 迁移原则

1. 原件不删除、不覆盖；新目录使用复制或规范化副本，并记录来源路径与 SHA。
2. 一份资料可有一个主分类和多个关联标签，不重复存储多个副本。
3. 每份资料必须有来源、时间、授权、质量、适用范围和状态元数据。
4. 个人经历、客户资料和私有数据默认归 E/D，不进入 A/B。
5. 旧平台规则和过期资料保留历史状态，不得作为当前规则直接命中。
6. 新资料先登记 metadata，再切段入库，再做检索和引用测试。
7. 未经评估，不批量搬迁 80 万级文本段，也不重建旧数据库。

## 当前结论

现有资料规模不等于通用商业能力成熟。旧知识含大量个人 IP/平台专用材料，RAG 的历史评测口径与当前代码默认参数存在版本不一致风险；在统一评测前，RAG 只能辅助定位，关键结论回到原始来源核验。
