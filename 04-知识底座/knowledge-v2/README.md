# 通用商业知识体系 V2

状态：治理方案已建立；历史知识未批量搬迁；RAG 运行指标待统一复测。

## 目标

将旧有以个人 IP/账号运营为中心的知识资产，逐步治理为支持通用商业操盘的 A-E 分层知识体系。迁移以“先分类、再验证、后搬迁”为原则，不做无差别复制，不删除原始材料。

## 分层

- A 通用商业认知：跨行业原理、战略、竞争、营销、经营、财务、组织、决策方法。
- B 行业与市场情报：行业结构、政策、市场规模、客户行为、技术趋势、竞争情报。
- C 专业领域知识：职能/专业/业务模式知识；个人 IP 与内容运营归入 C 的一个专业子域。
- D 具体业务项目知识：客户、产品、项目、投标、交付、运营和复盘材料。
- E 个人专属知识：个人经历、偏好、能力、私有数据和私人案例。

## 层间引用、继承与检索隔离

| 层 | 默认可用于哪些任务 | 默认检索规则 | 禁止的隐式继承 |
|---|---|---|---|
| A 通用商业认知 | 所有商业任务 | 通用默认层；优先检索已核验、未过期内容 | 不因项目或个人资料反向改写通用原则 |
| B 行业与市场情报 | 与行业/地域/市场相关的任务 | 必须匹配行业、地域、时间和来源有效期 | 不把单一企业情报泛化为行业事实 |
| C 专业领域知识 | 明确涉及该专业/职能/业务模式的任务 | 按专业标签显式检索；个人 IP 是独立子域 | 不把场景 SOP 直接升级为 A 层通用方法 |
| D 具体业务项目知识 | 对应项目及经授权的相关任务 | 必须匹配 project_id/customer_id 和访问权限 | 不跨客户、跨项目复用私有数据 |
| E 个人专属知识 | 明确涉及该个人且获授权的任务 | 默认关闭；按用户明确授权和最小范围检索 | 不向 A/B/C/D 自动扩散个人经历、偏好或隐私 |

### 继承规则

1. 检索段继承原知识卡片的来源、定位、授权、质量、有效期、敏感级别和核验状态；切段不得丢失或放宽这些属性。
2. 子卡片/摘要必须保留 parent knowledge_id 和原文 locator；摘要不能提高原文的核验等级或授权等级。
3. A 层原则可以被 B/C/D/E 的证据挑战，但只有经过跨来源验证、适用边界审查和治理审批后，才可形成 A 层修订候选。
4. B/C/D/E 的内容按需引用 A 层方法，但引用不代表内容自动继承 A 层的可信度。
5. D/E 的敏感信息不得进入共享向量索引；如需形成匿名化经验，必须先完成授权、脱敏、可迁移性和反例审查。
6. 所有跨层引用都记录 source knowledge_id、引用层、调用任务和访问主体，便于审计。

## 迁移原则

1. 原件不删除、不覆盖；新目录使用复制或规范化副本，并记录来源路径与 SHA。
2. 一份资料可有一个主分类和多个关联标签，不重复存储多个副本。
3. 每份资料必须有来源、时间、授权、质量、适用范围和状态元数据。
4. 个人经历、客户资料和私有数据默认归 E/D，不进入 A/B。
5. 旧平台规则和过期资料保留历史状态，不得作为当前规则直接命中。
6. 新资料先登记 metadata，再切段入库，再做检索和引用测试。
7. 未经评估，不批量搬迁全部历史知识段，也不重建旧数据库。先抽样验证分类、元数据继承、切段质量和权限隔离，再决定是否分批迁移。

## 当前结论

现有资料规模不等于通用商业能力成熟。旧知识含大量个人 IP/平台专用材料，RAG 的历史评测口径与当前代码默认参数存在版本不一致风险；在统一评测前，RAG 只能辅助定位，关键结论回到原始来源核验。
