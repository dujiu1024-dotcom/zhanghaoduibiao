# 旧知识资产迁移映射

原则：原件保持原位；先登记、分类和验证，再决定是否生成 V2 副本。下表是迁移策略，不代表批量迁移已经完成。

| 旧资产路径/类别 | V2 目标层 | 处理方式 | 状态 | 说明 |
|---|---|---|---|---|
| `04-知识底座/通用商业认知/` | A | 直接作为 A 层入口 | 已建立 | 本次新建总纲、能力地图、模型目录 |
| `knowledge/methodology/` 中通用战略/营销/经营方法 | A 或 C | 逐篇审计后规范化副本 | 待迁移 | 不按文件名直接判定通用性 |
| `knowledge/methodology/` 中抖音/内容平台方法 | C/个人 IP | 场景化保留 | 待标记 | 不能进入 A 层通用规则 |
| `knowledge/accounts/` | C/个人 IP | 保留原位，按需调用 | 场景专用 | 账号样本和平台经验 |
| `knowledge/sources/fulltext/law/` | A/B/C | 按法规主题和时效重新分类 | 待审计 | 记录生效/废止状态和官方来源 |
| `knowledge/sources/fulltext/official/` | B/C | 按机构、主题、日期归档 | 待审计 | 平台和供应商官方资料需设复核周期 |
| `knowledge/sources/secondhand/` | A/B/C | 二手材料单独标记 | 待审计 | 不冒充一手证据 |
| `knowledge/sources/metadata.csv` | V2 metadata | 字段映射后保留旧表 | 待映射 | 不直接覆盖旧元数据 |
| `catalog/` 与 77 个细类 | C/个人 IP | 保留为旧场景目录 | 场景专用 | 旧细类门槛不迁移为通用标准 |
| `rag/` SQLite 与检索脚本 | V2 检索服务候选 | 保留，先评测再决定改造 | 待评测 | 参数和报告口径需统一 |
| `图谱/` 账号旅程图谱 | C/个人 IP | 保留原图谱；通用图谱另行设计 | 场景专用 | 不直接作为企业经营因果图 |
| `experience/` 经验库 | D/E 或 C | 按项目/个人/领域重新标记 | 待审计 | 经验不可自动泛化为规律 |
| `00-战略与目标/` | A/D/E | 拆分通用方法、具体业务和个人信息 | 待拆分 | 保留历史决策链 |
| `03-决策与复盘/decision-log/` | D/E | 项目/个人层，脱敏后可抽象 | 待审计 | 仅在授权范围内复用 |
| `01-执行包/`、`02-调研与对标/` | C/个人 IP 或 D | 归入场景执行资产 | 场景专用 | 不作为通用商业方法库 |
| `05-给你看/` | D/E | 历史结论和用户视图 | 历史保留 | 含个人业务与客户信息，不能直接入 A 层 |

## 迁移批次

1. 批次 0：建立 V2 分类、元数据规范、覆盖矩阵（已完成）。
2. 批次 1：抽样 30 份代表资料，覆盖 A/B/C/D/E，完成分类和质量判定。
3. 批次 2：优先补齐 A 层战略、竞争、营销、经营、财务、决策核心知识。
4. 批次 3：迁移高价值 B 层行业/市场情报，建立有效期和更新责任。
5. 批次 4：把个人 IP 资料独立映射到 C 场景包。
6. 批次 5：按授权整理 D/E 私有项目和个人资料。

## 禁止事项

- 不批量搬迁全部知识文件或数据库段。
- 不删除旧来源或历史报告。
- 不把书目、摘要、经验条目当作已验证知识。
- 不将个人/客户敏感数据写入 A/B 层。
- 未完成来源、权限和有效期审查，不标记 active。
