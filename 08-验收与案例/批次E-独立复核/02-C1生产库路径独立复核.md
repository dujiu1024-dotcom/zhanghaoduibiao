# 阶段 8 批次 C / C1 生产库路径专项核查独立复核

- 复核对象：PR #44（本机只读采集）与 PR #47（生产库路径专项核查）
- 复核日期：2026-11-16
- 结论：**C1 证据可用于定位风险，但尚不能据此批准 C2 生产库复制/备份、路径切换或任何写操作**
- 范围：仓库源码与已提交脱敏报告的静态复核；未访问用户本机文件系统、进程句柄或数据库。

## 1. 已由报告/源码支持的发现

1. `rag.py` 当前定义 `DB_PATH = HERE / "kbase.db"`，即默认指向 `04-知识底座/rag/kbase.db`。
2. `connect(path=DB_PATH, create=True)` 在 `create=True` 时调用 `sqlite3.connect(path)`；SQLite 对不存在路径会创建数据库文件。该默认行为构成自动建库风险。
3. `cmd_init()`、`cmd_ingest()` 通过默认 `connect()` 进入创建路径。
4. `cmd_rebuild()` 在默认路径存在时先删除主库及 WAL/SHM，再调用默认 `connect()`；若默认路径不存在，仍会创建新库。该命令不会自动找到归档目录中的 3.8 GiB 数据库。
5. `catalog/check_data.py` 与 `验收/check_recall.py` 均硬编码默认路径；`work/three_sources.py` 使用无只读 URI 的 `sqlite3.connect()`，路径不存在时也可能留下空库。
6. PR #47 报告给出的当前归档库哈希与批次 A 冻结哈希不同。哈希不一致足以说明两个时点的文件内容校验值不同，但不能单凭此确定差异原因或当前是否仍有进程写入。

## 2. PR #47 报告中需要更正/降格的表述

### C1-R1：“唯一有效生产库”尚未证明

报告以数据库体积及 docs/segments 数量将归档路径称为“唯一有效生产库”。现有证据最多支持“本次扫描发现的唯一已知数据量较大的 SQLite 文件/候选数据副本”。尚未证明当前 Trae/RAG 实际运行进程使用该文件，也未排除仓库扫描范围外的副本或其他运行目录。

建议统一改称“当前扫描范围内唯一发现的非空、数据量较大的 kbase.db 候选库”，并将“生产库”身份标为 NOT_VERIFIED，直到有运行进程参数、实际打开文件句柄或应用配置证据。

### C1-R2：mtime 不等于活跃读写

文件 mtime 更新可作为文件内容发生变化的线索，但单次 stat 不能证明核查时仍有进程持续读写。要证明活跃写入，需要进程/文件句柄证据，或在明确授权的只读监测窗口中重复观测文件大小、mtime、哈希及 WAL/SHM 状态。

“当前处于活跃读写状态”应降格为“文件在两个采样时点之间发生过变化/当前状态未知”，除非补齐直接证据。

### C1-R3：无 WAL/SHM 文件不能证明已安全 checkpoint

未发现 `-wal`/`-shm` 文件，只能说明扫描时这些路径不存在；不能单独证明数据库已完成安全 checkpoint、处于静止状态或可直接复制。C2 必须使用 SQLite 一致性备份机制（例如受控的 backup API/一致性快照），并在隔离副本上恢复验证，不得直接复制正在使用中的数据库文件作为已验证备份。

### C1-R4：`connect(create=False)` 不等于严格只读

当前 `connect()` 即使传入 `create=False`，仍使用普通 `sqlite3.connect(path)`（读写连接），并执行 `PRAGMA journal_mode=WAL`。这不是只读连接保证，且 PRAGMA 可能改变数据库日志模式/文件状态。故不能把所有 `create=False` 调用统称为“无写风险”。

应区分：
- 不会因缺失路径自动创建数据库（代码先检查 path.exists）；
- 但连接本身仍非 SQLite `mode=ro` 只读连接；
- `journal_mode=WAL` 可能产生文件/状态变化；
- `retag` 本身会执行 DELETE/INSERT/COMMIT，属于明确写操作。

后续应分别实现真正的只读连接入口（URI `mode=ro`，不执行写 PRAGMA）和显式写连接入口，并对每个 CLI 子命令逐项标记读/写属性。

### C1-R5：rebuild 风险描述需精确

`cmd_rebuild()` 删除的是代码默认 `DB_PATH` 及其 WAL/SHM，不是自动删除 PR #47 报告中的归档路径。若默认路径不存在，它会直接创建一个新的空数据库再 ingest。若默认路径已指向重要数据库，则会先删除该路径，风险极高。报告应说明这两种条件分支，不能笼统暗示它会删除归档候选库。

### C1-R6：SHA 不匹配的原因仍未知

当前 SHA 与批次 A SHA 不一致，文件大小相同也不能证明数据库相同。候选原因包括数据库内容变更、checkpoint/写入或其他替换；当前材料不足以归因。不得把“SQLite 只读查询触发 checkpoint”作为已证实解释。需要确认批次 A 采集时连接方式、PRAGMA、文件是否有 WAL，以及本次哈希采样过程是否在任何连接/检查前完成。

## 3. C2 前置门禁（全部满足前不得复制/改路径/写库）

1. 用户明确指定要保护的源数据库物理路径，并确认其所有者/用途；不得仅凭“归档目录”名称推定。
2. 在不打开数据库写连接的前提下，采集源库主文件、WAL、SHM、相关备份文件清单与哈希；明确采集时间。
3. 确认进程与文件句柄状态；若无法确认静止，使用 SQLite 官方一致性备份机制，不直接文件复制。
4. 生成独立备份到用户指定位置，记录源/备份哈希、文件大小、SQLite integrity_check 结果及工具版本。
5. 在隔离目录恢复备份，执行 integrity_check、关键表计数、抽样文档/段落对照；不得将隔离恢复连接指向生产路径。
6. 由用户复核备份和恢复证据后，另行明确授权任何路径切换、代码默认值修改、生产 ingest/rebuild/retag 或迁移。
7. 任何生产写操作必须有变更清单、停机/锁定方案、回滚方案和执行后验证；当前报告不构成授权。

## 4. 可以先做的仓库侧整改（不触碰数据库）

- 将 `KBASE_DB` 路径配置能力纳入代码修复，但默认路径仍保持现状，不能猜测用户本机真实库路径。
- 禁止 `connect()` 在隐式默认路径上自动建库；创建数据库必须由明确的 init/测试命令显式授权，并且不能覆盖已存在文件。
- `rebuild` 增加显式确认参数/交互确认，并在目标路径不属于明确指定的测试/目标库时拒绝执行。
- 为只读命令使用 `mode=ro` 连接，禁止只读入口执行 `PRAGMA journal_mode=WAL`。
- 修复 `check_data.py`、`check_recall.py`、`three_sources.py` 的路径分散与只读保证；统一从配置读取路径。
- 添加无数据库依赖的单元测试：缺失路径时只读命令不得创建文件；rebuild 未显式确认时不得删除文件；路径覆盖可正确解析；只读命令不触发写 PRAGMA。

这些改动应单独形成代码 PR，先通过静态测试与临时测试目录验证。任何真实库路径切换仍须用户确认。
