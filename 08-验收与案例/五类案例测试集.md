# 五类商业案例测试包

## 案例清单

| ID | 类型 | 是否依赖个人资料 | 主要测试能力 |
|---|---|---|---|
| CASE-01 | 传统企业战略转型 | 否 | 战略取舍、能力迁移、资源配置、现金门槛 |
| CASE-02 | 新进入者市场竞争策略 | 否 | 市场边界、替代分析、竞争反应、进入策略 |
| CASE-03 | 新产品上市与营销增长 | 否 | 客户购买链、价值主张、定价、漏斗与付费验证 |
| CASE-04 | 收入增长但持续亏损 | 否 | 财务复算、根因假设、现金风险、90 天经营改善 |
| CASE-05 | 个人 IP 商业闭环 | 独立场景输入 | 场景规则隔离、定位、产品化、获客与付费验证 |

- `案例输入/CASE-01-传统企业战略转型.md`
- `案例输入/CASE-02-新进入者市场竞争策略.md`
- `案例输入/CASE-03-新产品上市与营销增长.md`
- `案例输入/CASE-04-收入增长但持续亏损.md`
- `案例输入/CASE-05-个人IP商业闭环.md`

全部企业、人物和数据均为虚构模拟。输入文件只包含首轮可见信息，不包含参考结论或反证注入内容。

## 盲测规则

1. 每个案例使用独立的新会话，不复用其他案例上下文。
2. 每轮只提供一个案例输入文件；不要把参考答案、评分说明或挑战证据放进被测 TRAE 工作区。
3. 首轮输出完成后，再从独立参考材料中取对应反证注入卡，作为第二轮用户输入。
4. 至少 CASE-01、CASE-02、CASE-04 作为正式盲测；建议五类全部盲测。
5. 分别保存专家原始交付、总控综合结果、黑板文件和工具调用记录。
6. 评分人员在首轮输出冻结后才查看参考要点；不得提前把参考要点写入规则、Skill 或知识库。

## 通用输出要求

- 任务简报、目标/约束和风险级别；
- 事实/推断/假设/未知/偏好/建议分离；
- 关键证据及来源定位；
- 关键变量、竞争性假设和缺口；
- 专家选择理由和独立交付；
- 备选方案、不行动方案、取舍和反方挑战；
- 决策门槛、审批事项、风险和退出条件；
- 执行计划、责任、期限、指标和复盘节点。

## 测试边界

此测试包用于评估 TRAE 项目配置，不允许用 ChatGPT 的模拟答复替代用户本机 TRAE 的运行记录。
