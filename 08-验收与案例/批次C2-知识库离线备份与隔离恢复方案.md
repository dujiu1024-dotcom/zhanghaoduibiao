# 批次 C2｜知识库离线备份与隔离恢复方案

- 状态：**方案已制定；真实备份与隔离恢复未执行（NOT_VERIFIED）**
- 适用：阶段 8 / Issue #28
- 执行基准：用户本机 Trae CN 3.4.20 与其实际知识库环境
- 安全原则：先只读盘点；备份、恢复、生产变更均须独立授权

## 1. 目标与禁止事项

本方案用于在任何知识库写入、迁移、重建索引或生产配置变更之前，建立可验证的回退基础。验收对象不是“备份文件存在”，而是：备份范围完整、校验可复核、隔离副本可恢复、恢复结果与备份时点一致，并且生产环境未被触碰。

在用户明确授权前，执行人员不得：
- 复制、移动、改名、压缩、删除或覆盖生产数据库及其 WAL/SHM 文件；
- 对生产数据库执行写 SQL、checkpoint、vacuum、ingest、rebuild、retag 或迁移；
- 改动生产环境变量、检索参数、索引、目录权限或服务配置；
- 将知识库原文、客户资料、个人资料或密钥上传到 GitHub、聊天或公共存储；
- 将“只读统计”“备份方案”或模拟恢复描述为已完成的备份/恢复证据。

## 2. 备份前资产盘点

在只读阶段先建立资产清单，逐项记录实际路径、类型、体积/数量、敏感级别、所属知识层、是否可重建、依赖关系和责任人。不得凭仓库默认路径推断本机实际路径。

| 资产类别 | 盘点内容 | 完整性注意事项 |
|---|---|---|
| 主数据库 | 实际数据库文件、SQLite 版本、schema 版本 | 记录绝对路径、大小、mtime、SHA-256；不直接复制活动 DB |
| SQLite 伴随文件 | WAL、SHM、journal 是否存在 | 活动数据库必须使用一致性快照方法，不能只复制主 DB |
| 原始知识文件 | PDF、DOCX、MD、网页归档、附件等 | 保留相对路径、文件数、总字节数及逐文件校验清单 |
| 元数据与映射 | metadata、标签、层级、来源映射、权限记录 | 确认是否在数据库之外，是否存在独立版本 |
| 检索配置 | 参数、过滤规则、切片/重排配置 | 记录实际生效值与来源；密钥只记录变量名，不记录值 |
| 运行依赖 | Python、依赖锁文件、模型名称/版本、向量模型 | 区分可下载依赖与不可替代的本地模型资产 |
| 运行环境 | 启动参数、服务地址、权限主体 | 凭据、token、个人路径需脱敏，不纳入普通证据包 |

盘点输出只提交脱敏统计、文件指纹和路径代号；敏感原文和密钥留在用户控制的本机安全位置。

## 3. 授权与执行前检查点

真实备份前必须由用户明确确认以下事项，授权应限定范围、目的、时间和目标位置：
1. 允许读取/复制的资产路径和资产类别；
2. 备份目的地（独立磁盘或受控加密目录）及可用空间；
3. 是否包含原始文件、数据库、配置和本地模型；
4. 加密方式、密钥保管人、访问人员与保留期限；
5. 允许使用的备份工具/脚本及是否允许短暂停止写入服务；
6. 是否允许创建隔离恢复副本（与生产目录完全分离）。

授权缺失、路径不清、活动写入状态不明、磁盘空间不足、权限边界不清或发现疑似损坏时，停止执行并登记 BLOCKED。

## 4. 一致性备份方法

### 4.1 SQLite 数据库

- 优先采用 SQLite Online Backup API（例如 Python sqlite3.Connection.backup）生成一致性快照；也可采用经验证的 SQLite 原生备份工具。
- 备份前记录数据库连接/服务写入状态。若业务允许且经用户授权，可暂停写入；不得擅自停止服务。
- 不得在数据库仍可能写入时仅复制主 .db 文件。WAL 模式下，已提交事务可能仍位于 WAL 中。
- 备份完成后关闭备份连接，对备份文件计算 SHA-256；记录源库与备份库的 schema 版本、表清单及行数统计。
- 若采用文件系统快照，必须证明快照具备数据库一致性；否则不得作为有效备份。

### 4.2 原始文件、元数据与配置

- 对原始知识文件采用保留目录结构的复制/归档方式；逐文件计算 SHA-256，并生成 manifest。
- 数据库快照与原始文件清单必须绑定同一备份批次 ID 和时间窗口。
- 配置文件需脱敏；密钥不进入归档。对密钥仅记录“存在/缺失、变量名、由谁保管”。
- 对模型文件记录模型 ID、版本、文件指纹和获取方式；只有在授权范围内才复制大体积模型文件。

### 4.3 备份包清单

每次备份至少生成：
- backup_id、执行人、授权记录编号、开始/结束时间、主机与软件版本；
- 资产类别、源路径代号、备份目标、文件数量、字节数；
- 每个文件的相对路径、大小、SHA-256；
- 数据库表清单、schema 版本、只读行数统计；
- 加密算法/工具版本、密钥保管方式（不得记录密钥本身）；
- 异常、跳过项、失败项和完整性结论。

## 5. 隔离恢复验证

恢复验证必须在隔离目录或隔离设备中进行，不得覆盖生产目录，不得连接生产写入服务，不得让恢复副本被生产检索进程自动发现。

### 5.1 隔离条件

- 目标目录使用明确的隔离标识，例如 `restore-validation/<backup_id>/`；
- 默认断开外部写入、自动同步和生产索引任务；
- 恢复副本使用只读权限进行结构核验；需要启动应用验证时，使用隔离配置、独立端口和独立数据路径；
- 恢复验证不得把副本数据回写生产环境。

### 5.2 验证步骤

1. 校验备份包 manifest 与所有文件 SHA-256。
2. 解密/解包到隔离目录，记录实际文件数、总字节数和失败项。
3. 对 SQLite 副本执行只读 `PRAGMA integrity_check`，要求结果为 `ok`；记录 schema、表名和关键表行数。
4. 将恢复副本统计与备份时统计对照；解释所有差异，不得静默忽略。
5. 对原始文件按 manifest 复核指纹，并抽样打开文件，确认内容可读。
6. 抽取脱敏样本，核验 metadata、来源定位、知识层、授权、敏感级别、有效期等字段完整性。
7. 如经单独授权进行隔离检索冒烟测试，验证可启动、可查询、引用定位可回到原始文件；不以此代替完整 RAG 评测。
8. 记录清理隔离副本的条件；未获授权前保留或清理均需遵循用户指定的保管策略。

### 5.3 通过标准

- 所有纳入范围的文件均有 manifest 记录，校验通过率 100%；排除项有理由和责任人。
- 数据库完整性检查通过；关键表结构与行数差异均可解释。
- 原始文件抽样可读，metadata 与来源定位可追溯。
- 隔离恢复过程未访问或修改生产数据。
- 任何未恢复资产、未验证依赖或不一致均明确标记 NOT_VERIFIED / BLOCKED。

## 6. 回滚策略与变更门禁

备份/恢复成功不等于允许迁移。任何后续变更须另行提交：
- 变更目标、范围、预期结果和影响分析；
- 变更前后文件/数据库对象清单；
- 迁移批次 ID、幂等策略、失败处理和停止条件；
- 回滚触发条件、回滚步骤、责任人和预计影响；
- 用户对该次具体变更的明确授权。

回滚优先恢复到已验证的隔离快照所对应版本。生产恢复前必须再次确认目标环境、停写窗口、当前状态备份和用户授权；不得将隔离恢复测试直接覆盖生产。
