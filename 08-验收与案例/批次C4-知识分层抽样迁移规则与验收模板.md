# 批次 C4｜知识分层抽样迁移规则与验收模板

- 状态：**迁移规则与模板已制定；未执行抽样复制、写库或迁移（NOT_EXECUTED）**
- 适用：阶段 8 / Issue #28
- 目标：以可追溯的小样本验证 A–E 分层、元数据继承、权限隔离和检索质量，不做全量搬迁

## 1. 迁移总原则

1. 原始资料保持原位、只读保留；迁移目标为受控副本或规范化知识卡，不覆盖、不删除原件。
2. 先分类、再验证、后搬迁；不得以目录名、文件名或关键词直接决定知识层。
3. 每条样本必须能追溯到原始来源、locator、授权证据、版本、目标层和迁移决定。
4. 一份资料只设一个主知识层，可有多个主题标签；避免多份内容副本造成版本漂移。
5. 摘要、切片、向量和派生卡片不得提高原件的可信度、授权等级或时效状态。
6. 个人与客户数据默认隔离；无明确授权、用途不清或无法脱敏的资料不得进入共享知识层。
7. 真实复制、写库、改标签、建索引、重建或删除操作必须等待 C2 备份与隔离恢复通过，并取得用户对具体变更的明确授权。

## 2. A–E 分层判定规则

| 层级 | 定义 | 典型纳入 | 排除/限制 |
|---|---|---|---|
| A 通用商业认知 | 跨行业可复用的原理、方法和框架 | 战略、竞争、营销、经营、财务、组织、决策方法 | 单一公司经验未经跨案例验证，不直接升为 A |
| B 行业与市场情报 | 有明确行业、地域、时间和来源的外部信息 | 行业结构、政策、市场规模、客户行为、竞争情报 | 必须记录发布日期、有效期和适用地域；过期信息标记历史 |
| C 专业领域知识 | 特定职能、专业或业务模式的方法与 SOP | 内容运营、个人 IP 专业方法、销售、供应链等 | 不得把个人私密经历混入通用专业方法 |
| D 业务项目知识 | 对应客户、项目、产品或交付的私有资料 | 项目方案、客户访谈、报价、项目复盘 | 必须绑定 project/customer 范围和访问权限，不跨项目检索 |
| E 个人专属知识 | 特定个人的经历、偏好、能力和私有数据 | 个人履历、偏好、私人案例和个人数据 | 默认关闭；只有明确涉及该个人且获授权时才可检索 |

### 2.1 主层决策树

1. 是否包含可识别个人信息、私人经历或个人专属偏好？是则优先 E。
2. 是否包含客户、合同、项目、报价或具体交付信息？是则优先 D，并进一步标记敏感级别。
3. 是否为行业/地域/市场动态事实？是则 B，并校验时间与来源。
4. 是否为明确专业领域的方法或 SOP？是则 C。
5. 是否具备跨行业、跨案例的稳定适用性和充分证据？是则可候选 A。
6. 无法判断时标记 `UNCLASSIFIED`，隔离待审，不得默认放入 A。

同一资料混合多个层级时，优先拆分为可独立授权、独立定位的知识单元；无法安全拆分时按最高敏感层级管理。

## 3. 迁移前置门禁

迁移前必须全部满足：
- C1 本机资产、权限和实际存储路径已完成只读盘点；
- C2 备份范围已核验，真实备份成功且 SHA-256/manifest 完整；
- C2 隔离恢复验证通过，差异均已解释；
- 目标目录、数据库、索引和配置已明确；
- 样本来源、授权、隐私和知识层判定已复核；
- 迁移脚本/步骤经过 dry-run，输出变更清单且未写入；
- 回滚步骤、停止条件、责任人和验证方法已明确；
- 用户对本次迁移范围、样本、目标和时间窗口作出明确授权。

任何一项缺失，迁移状态为 BLOCKED。不得以“用户说继续推进项目”替代对具体生产写操作的明确授权。

## 4. 抽样设计

### 4.1 抽样框

先建立完整抽样框，至少包含：
- 知识层候选（A/B/C/D/E/UNCLASSIFIED）；
- 来源类型（原始文档、人工知识卡、网页、项目材料、数据库记录）；
- 文件/知识单元 ID、版本、大小、创建/更新时间；
- 授权证据状态、敏感级别、有效期；
- metadata 完整性、重复/冲突标记、质量等级；
- 是否已被索引、是否可能被其他知识单元引用。

抽样框只记录脱敏 ID 和统计，不把敏感原文复制到仓库。

### 4.2 分层抽样方法

- 先按 A–E、来源类型、风险等级和元数据完整性分层。
- 每个实际存在的知识层至少抽取若干代表样本；低频高风险层（尤其 D/E）单独列出，不得被大样本层淹没。
- 试点建议以 30–50 个知识单元作为总体规模；若总体规模较小则全量审查。该试点用于验证流程和发现分类问题，不宣称统计代表性或总体质量置信度。
- 在每层内随机抽样，并有目的地补充高风险样本：重复项、冲突项、过期项、无来源项、授权不明项、跨层引用项。
- 对每个样本记录抽样方法、随机种子/抽样批次、入选理由和替补规则；不得只挑选容易通过的样本。
- 若抽样后发现系统性分类或权限错误，暂停迁移，扩大审计范围并重新评估。

### 4.3 样本编号

使用不含客户名、个人名或原始文件名的编号，例如 `C4-A-0001`。映射到真实路径的私有索引仅保存在用户控制的本机目录，不提交 Git。

## 5. 元数据最低要求

每条迁移候选至少具备以下字段；字段值不明确时填 `unknown` 并阻止进入目标共享层，不能猜测。

| 字段 | 要求 |
|---|---|
| knowledge_id | 全局唯一、稳定 ID |
| source_id / source_locator | 原始来源编号与页码/章节/段落等定位 |
| source_hash | 原始文件 SHA-256 或可复核内容指纹 |
| source_type | 文档、网页、项目材料、人工知识卡等 |
| title | 脱敏标题或内部标题 |
| primary_layer | A/B/C/D/E/UNCLASSIFIED 之一 |
| tags | 主题标签；不能代替主层 |
| created_at / updated_at | 来源时间与本次处理时间，时区明确 |
| valid_from / valid_until | 适用有效期；不适用时说明 |
| authorization_status | verified / restricted / denied / unknown |
| authorization_evidence | 授权记录代号，不存敏感凭据 |
| sensitivity | public / internal / confidential / personal / restricted |
| quality_status | verified / reviewed / unverified / disputed |
| lifecycle_status | active / historical / deprecated / quarantined |
| parent_knowledge_id | 派生内容的父级知识 ID |
| access_scope | 允许访问的用户、项目或任务范围 |
| migration_batch_id | 迁移批次编号 |
| review_owner | 审核责任人 |

## 6. 冲突、重复与风险处置

| 情况 | 处理规则 | 默认迁移决定 |
|---|---|---|
| 内容重复且哈希一致 | 保留一个规范记录，其他记录登记别名/来源 | 可候选合并，原件不删 |
| 内容相似但版本不同 | 比较发布时间、适用范围和差异 | 分版本保留，不自动覆盖 |
| 来源冲突 | 记录冲突主张、来源权威性、时间和适用范围 | 隔离待裁决，不强行合并 |
| 已过期内容 | 保留历史价值，标记 valid_until/lifecycle | 不作为当前有效依据 |
| 无来源/无 locator | 尝试回溯原件；无法回溯则标记 unverified | 不进入 A/B 共享层 |
| 授权不明/拒绝 | 联系权利人或隔离 | 不迁移 |
| D/E 敏感资料 | 保持项目/个人隔离，最小权限 | 不进入共享索引 |
| 摘要与原文不一致 | 以原文复核，保留差异记录 | 暂停派生卡迁移 |
| 标签与原文不符 | 修正候选标签并记录依据 | 不以旧标签直接入库 |

不得仅凭文件名、标签或向量相似度自动合并冲突资料。

## 7. Dry-run 与实际迁移步骤

### 阶段 0：只读抽样

输出抽样框、样本编号、分类建议、风险和元数据缺口。此阶段不复制文件、不写库。

### 阶段 1：人工复核

由内容责任人核验来源、定位、授权、敏感级别、适用范围和主层；有争议的样本进入隔离队列。

### 阶段 2：Dry-run

在隔离环境对样本执行分类/映射模拟，输出：
- 计划新增/更新/跳过的知识单元；
- 目标层、目标路径和访问范围；
- metadata 字段差异；
- 重复、冲突、拒绝和隔离列表；
- 预计文件数、数据库行数和索引变化；
- 可逆性和回滚点。

Dry-run 必须证明不写生产文件、不连接生产数据库写入端点、不触发自动索引。

### 阶段 3：用户逐批授权

用户审阅 dry-run 结果后，对具体批次 ID、样本范围、目标位置、操作类型和时间窗口作出明确授权。授权不自动延伸到后续批次。

### 阶段 4：受控执行（当前未获授权，不执行）

执行时小批量、幂等、有日志；每批完成后立即校验 metadata、权限、来源定位和检索行为。出现任何未授权访问、数量异常、哈希不符或不可解释差异，立即停止，不继续下一批。

### 阶段 5：回归与归档

对已迁移样本执行只读抽检和 C3 评测相关回归；保存变更前后清单、差异、日志、校验和、用户授权和复核签名。不得删除原始资料。

## 8. 验收标准

单条样本必须同时满足：
- 原始来源、定位与 SHA 指纹可追溯；
- 主层判定有理由，适用范围清楚；
- 授权状态已核验，访问范围未扩大；
- 敏感级别、有效期、质量和生命周期字段完整；
- 派生内容保留 parent ID，不提高原文可信度；
- 重复/冲突/过期状态已按规则处理；
- 目标层检索不会造成跨项目或个人知识泄漏；
- 迁移前后数量与指纹差异可解释。

批次层面还必须满足：
- C2 备份与隔离恢复已 PASS；
- 全部实际写入均有用户明确授权；
- 无未解决 P0/P1 权限、来源或数据完整性问题；
- 原件未删除/覆盖；
- 失败项、跳过项和隔离项均有清单；
- 回滚路径经过验证或明确标记 BLOCKED。
