# RAG 正式题集构建与冻结规范

## 1. 目的与边界

本规范用于阶段 8 建立可复现的 RAG 真实评测题集。当前仓库中的 question-template.jsonl 仅为格式示例，不是正式题集；历史 20/12、240/60 等成绩未核验，不得作为本次基线。

正式题集必须来自当前知识库快照和可定位原文。不得为了凑题量制造 gold，不得将模型生成的答案反过来当作标准答案。

## 2. 四类数据集

| 集合 | 用途 | 允许用于调参 | 访问规则 |
|---|---|---|---|
| 正向集 | 验证可回答问题的召回、排序、引用和忠实度 | 是 | 标注人员与调参人员可访问 |
| 负向集 | 验证无答案时拒答、识别相近干扰 | 是 | 明确标记不可回答原因 |
| 对抗集 | 过期、冲突、相似关键词、跨域/跨语言干扰 | 是 | 保留干扰项和期望行为 |
| 独立保留集 | 评估冻结候选版本的泛化能力 | 否 | 独立保管；调参人员不得访问题目与 gold |

## 3. 每题必备字段

建议 JSONL 每行一题，至少包含：

- question_id：稳定唯一编号。
- query：真实用户表达，不暴露 gold。
- expected_answerable：true/false。
- gold_source_ids：标准来源知识 ID；负向题为空数组。
- gold_locators：页码/章节/段落/表格/原文片段定位。
- relevance_grades：候选来源的人工相关性等级，用于 nDCG。
- domain、difficulty、dataset_split、dataset_version。
- confounders：干扰来源及干扰原因。
- expected_behavior：回答、限定回答、拒答或外部取证。
- freshness_as_of：时效判断基准时间。
- sensitivity_class：题目和 gold 的敏感级别。
- annotator、reviewer、annotation_evidence：标注和复核证据。

## 4. 标注规则

1. 每道正向题至少有一个可访问、可复核的 gold source 和 locator；仅有标签、标题或文件名不构成证据。
2. gold locator 必须能支持问题中的关键主张；若原文只能支持部分答案，标注为部分可回答并写清边界。
3. 负向题必须记录“库内无答案”的核查范围、相近干扰来源及期望拒答行为。
4. 对抗题必须记录干扰机制：过期、冲突、实体相似、词面相似、跨语言或跨领域。
5. 相关性等级在题集版本内冻结；不得因模型表现不佳而事后修改 gold。
6. 争议题由第二位标注者复核；未解决争议题不进入正式评分集。
7. 个人/客户敏感信息不得进入通用题集；必须脱敏并有授权依据。

## 5. 题集冻结

冻结前记录：
- 知识库快照 ID 与文件清单哈希；
- 题集版本、每类题目数量和 JSONL SHA-256；
- gold 来源与 locator 复核记录；
- 标注人员、复核人员、冻结时间；
- 保留集保管人和访问控制；
- 本次评测目的与允许调参范围。

冻结后任何修改都必须升级题集版本、生成差异报告，并重新计算哈希。保留集不得参与调参，也不得把保留集错误样本直接反馈给规则/提示优化。

## 6. 最低可执行要求

先做小规模可人工核验的试运行集，确保流程、指标和逐题日志正确；正式基线规模由知识库覆盖和标注能力决定，不以题量作为质量替代。至少同时报告样本量、分子/分母、指标值、置信区间和逐题错误。具体 k 值、相关性等级和通过阈值须在第一次正式运行前冻结，不得看完结果后再设门槛。
