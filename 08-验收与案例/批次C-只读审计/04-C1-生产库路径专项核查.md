## 3. 自动建库风险评估

### 3.1 风险来源一：rag.py connect() 默认参数

```python
# rag.py 第 189-192 行
def connect(path: Path = DB_PATH, create: bool = True) -> sqlite3.Connection:
    if not create and not path.exists():
        sys.exit(f"数据库不存在：{path}，先跑 `python rag.py rebuild`")
    conn = sqlite3.connect(path)   # ← 关键：SQLite 标准行为，路径不存在则自动创建空文件
```

**风险逻辑**：
1. `sqlite3.connect(path)` 在 Python sqlite3 模块中，当 `path` 指向不存在的文件时，会**自动创建一个空的 SQLite 数据库文件**（约 0-4KB，含 SQLite header）。
2. `create=True` 分支的 `if create:` 只是额外执行 `SCHEMA` 和迁移，但**不拦截 sqlite3.connect() 自身的自动建库行为**。
3. 只有 `create=False` 时，`if not create and not path.exists()` 才会触发 `sys.exit`，拦截自动建库。

### 3.2 风险来源二：三个默认路径命令

| 命令 | 函数 | 建库条件 | 风险等级 |
|------|------|---------|---------|
| `python rag.py init` | `cmd_init` → `connect()` | DB_PATH 不存在 → sqlite3.connect 自动建空库 → 执行 SCHEMA | **高**。空表 + schema 到位，但无任何文档/段落/向量 |
| `python rag.py ingest` | `cmd_ingest` → `connect()` | 同上 | **高**。在空库上执行全量 ingest，耗时巨大但产出正确 |
| `python rag.py rebuild` | `cmd_rebuild` → 先 unlink 再 connect | DB_PATH 存在 → 强制删除 → connect 新建 | **极高**。误跑即丢库 |

### 3.3 风险来源三：work/three_sources.py 无保护

```python
# work/three_sources.py 第 5, 9 行
BASE = '04-知识底座/'
db = sqlite3.connect(BASE + 'rag/kbase.db')  # ← 无 create=False、无 mode=ro
```

一次性统计脚本，若被主动调用且路径不存在，会自动建空库后立刻因 SELECT 报错（空库无表），但**已经留下了空壳文件**。

### 3.4 风险不会触发的场景

- 所有 `create=False` 调用：路径不存在时 sys.exit 退出
- 所有 `mode=ro` URI 连接：路径不存在直接报错
- `build_index.py`：不使用 SQLite
- `b-base/build_bbase.py`：独立库，路径完全不同
