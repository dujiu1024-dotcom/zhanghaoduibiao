- 运行基准：用户本机 Trae CN 3.4.20 对应的实际 RAG 环境
- 目的：建立可复核、可重复、与调参隔离的评测流程

## 1. 评测边界与当前基线

当前仓库中的历史题集与历史分数不得自动视为正式基线：
- 现有 20 条正向题、12 条负向题只能作为历史开发集候选，须先核验题目、gold 标注、重复关系和来源。
- 历史 240/60 题集及历史命中率记录，在未找回原始文件、脚本、版本和完整报告前，标记为未核验历史记录。
- `evaluation/question-template.jsonl` 的格式示例不是评测题集。
- 源码默认参数不代表本机实际生效参数；运行时必须记录环境变量覆盖、命令行参数和最终配置。
- 本文件不包含正式 holdout 题目、答案或批次 D 盲测参考材料。

批次 D 的私有参考答案、评分参考点和反证注入卡严禁进入本评测目录、知识库、仓库、被测工作区或被测会话。C3 数据集与 D 盲测材料是不同资产，必须分别保管和授权。

## 2. 评测集分区与访问控制

| 数据集 | 用途 | 可否调参 | 可否进入检索索引 | 保管要求 |
|---|---|---:|---:|---|
| 开发集 | 日常调试、错误定位 | 是 | 仅在明确测试环境中 | 版本化，保留变更历史 |
| 验证集 | 候选配置比较、阈值选择 | 有限 | 仅在测试环境中 | 访问留痕，不作为最终成绩 |
| 独立保留集（holdout） | 最终泛化评估 | **否** | **否** | 独立保管，候选版本冻结后才可运行 |
| 对抗/安全集 | 过期、冲突、权限和诱导测试 | 不得据其逐题定向过拟合 | 不得写入生产索引 | 单独版本与访问记录 |

独立保留集管理规则：
1. 题目编制人、gold 标注人、运行人和评分人尽可能分离；至少保留访问记录。
2. holdout 原始题目与 gold 答案不得用于提示词、规则、标签、索引或参数调试。
3. 运行前冻结题集版本、文件 SHA-256、代码 commit、脚本指纹、模型和知识库快照。
4. 只在候选系统版本冻结后，由保管人按受控流程释放评测输入；运行人不得看到 gold。
5. 评分完成后，先归档原始结果，再向整改人员披露失败类别与必要证据；不得把完整 holdout 回灌为调参数据。
6. 若 holdout 内容已泄漏或参与过调参，立即降级为开发/验证集，重新建立独立集并记录原因。
7. 任何 holdout 更新均产生新版本，旧版本及其成绩保留，不得覆盖历史记录。

## 3. 题目结构与标注要求

建议每条题目采用 JSONL 一行一个 JSON 对象。以下为字段规范示意，不是真实评测题：

```json
{
  "question_id": "C3-POS-0001",
  "dataset_version": "c3-dev-1.0.0",
  "split": "dev",
  "category": "positive_retrieval",
  "query": "待评测查询文本",
  "expected_answerable": true,
  "gold_sources": [
    {
      "source_id": "脱敏来源编号",
      "locator": "章节/页码/段落定位",
      "supporting_claim": "该来源支持的关键主张"
    }
  ],
  "domain": "strategy",
  "difficulty": "medium",
  "confounders": [],
  "expected_behavior": "应召回并基于证据回答",
  "permission_scope": ["A"],
  "freshness_requirement": null,
  "annotator": "标注者代号",
  "adjudication_status": "reviewed"
}
```

字段约束：
- `question_id` 全集唯一；不得复用或重排后丢失历史 ID。
- `split` 只能为 dev / validation / holdout / adversarial。
- `expected_answerable` 必须由实际知识库证据决定；不得因“常识上知道”而标为可回答。
- `gold_sources` 必须包含可复核来源和精确 locator；无答案题为空数组并说明原因。
- `permission_scope` 记录允许访问的知识层/项目范围，不写真实敏感内容。
- 每条题目需有标注者和复核状态；争议题不得进入正式评分集。

## 4. 必测维度与用例构造

### 4.1 正向召回

测试库内确有证据的查询。检查 gold source/locator 是否进入 Top-k，是否被重复片段或无关高相似文档挤出。覆盖战略、竞争、营销、经营、财务、组织、商业模式、风险和研究等领域，并覆盖简短/复杂查询。

### 4.2 负向拒答

测试知识库确实无答案、来源缺失、定位不完整或证据不足的查询。系统应明确说明未知/缺口，不能用一般常识补成库内事实，也不能编造引用。记录正确拒答与错误硬答。

### 4.3 对抗检索

至少覆盖：
- 关键词相似但业务对象/语义不同；
- 过期规则或已失效政策；
- 多来源互相冲突；
- 新旧版本并存；
- 标签相关但原文不支持；
- 跨行业/跨地域误迁移；
- 同名实体、简称和跨语言实体；
- 诱导性查询要求系统确认题目中不存在的事实。

### 4.4 引用准确性

逐条检查引用来源是否真实存在、locator 是否指向对应原文、引用是否支持其绑定的事实主张。标签命中、摘要相似或同主题片段不等于原文支持。报告引用准确率和引用覆盖率，不能只报告引用数量。

### 4.5 权限与知识层隔离

至少验证：
- 通用任务默认不检索 E 个人专属层；
- D 项目资料不跨项目/客户暴露；
- 敏感内容不因摘要、切片或向量索引丢失权限属性；
- 任务明确授权后只在授权范围内访问；
- 未授权时拒绝或脱敏，不以“相关性高”绕过权限。

### 4.6 时效性

对于动态情报、政策、价格和市场数据，核验来源日期、有效期和当前状态；过期资料只能作为历史信息，不得作为当前规则直接回答。

## 5. 指标与计算口径

每项指标均按逐题原始记录计算，按数据集、领域、难度、知识层分层汇总，并报告分子、分母、样本量。

| 指标 | 口径 |
|---|---|
| Recall@k | 有答案题中，Top-k 至少命中一个 gold source/locator 的题数 ÷ 有答案题总数 |
| Precision@k | 每题 Top-k 相关候选数 ÷ 返回候选数，再按题宏平均；空候选题单列 |
| MRR | 每题第一个 gold 候选排名倒数，未命中记 0，跨题宏平均 |
| nDCG@k | 按冻结的相关性等级计算 DCG@k/IDCG@k，再跨题宏平均 |
| Answerability precision | 系统判可回答且实际可回答题数 ÷ 系统判可回答题数 |
| Answerability recall | 系统判可回答的真实可回答题数 ÷ 真实可回答题数 |
| Negative abstention rate | 负向集上正确拒答题数 ÷ 负向题总数 |
| Faithfulness | 得到证据支持的事实主张数 ÷ 回答事实主张总数 |
| Citation accuracy | 真实且支持对应主张的引用数 ÷ 被核验引用数 |
| Citation coverage | 至少有有效支持引用的事实主张数 ÷ 需要证据支持的事实主张总数 |
| Stale-hit rate | 将过期/失效资料作为当前依据的题数 ÷ 含过期干扰题数 |
| Sensitive leakage | 未授权敏感信息输出事件数；关键泄露零容忍 |

不得将 Recall@k、Answerability recall、答案覆盖率或相似度阈值混称为一个指标。对人工判断指标，至少由一名独立复核者抽检；争议样例记录裁决理由。

## 7. 评分规则与失败归因

每个维度 0–4 分：
- 4：完全满足，证据完整，无实质偏差；
- 3：基本满足，有轻微缺陷但不影响关键结论；
- 2：部分满足，存在可见缺口或需要人工纠正；
- 1：严重不足，关键证据/行为错误；
- 0：未完成、不可用或触发安全否决。

失败标签至少包括：
- QUERY_UNDERSTANDING
- SOURCE_MISSING
- RETRIEVAL_MISS
- RANKING_NOISE
- STALE_SOURCE
- CONFLICT_NOT_HANDLED
- UNSUPPORTED_CLAIM
- CITATION_MISMATCH
- FALSE_ANSWER
- OVER_REFUSAL
- PERMISSION_BYPASS
- PERSONAL_LAYER_LEAK
- PROJECT_SCOPE_LEAK
- METADATA_LOSS
- NOT_OBSERVABLE

每个失败项记录严重度 P0–P3、根因模块、可复现步骤、受影响题目、证据位置和建议修复。权限越界、敏感泄露、关键编造来源或引用伪造属于一票否决，不得由总体平均分抵消。

## 8. 执行顺序与冻结门禁

1. 盘点现有题集、脚本、gold 标注和历史报告，确认开发集/验证集用途。
2. 获取 C1 本机只读快照：数据库指纹、实际参数、模型、代码 commit 和索引状态。
3. 建立题集版本和来源映射；去重、复核 gold locator，争议题隔离。
4. 独立创建并保管 holdout；计算哈希并登记保管人与访问权限。不得在调参阶段查看 gold。
5. 先冻结候选代码、模型、参数、知识库快照和脚本，再运行 holdout。
6. 保存逐题原始输出和机器可读记录；评分者独立核验引用、忠实度和权限。
7. 生成报告，复核统计口径和失败归因。
8. 若系统整改，开发/验证集可用于迭代；holdout 仅按重新冻结的候选版本受控重测。泄漏即降级并重建。

C2 备份与隔离恢复门禁未通过时，不进行任何可能写入、迁移或重建的评测准备动作。纯只读评测是否可运行，仍需确认其脚本不会创建缓存、更新索引或写入数据库；不能证明只读时先停止。
