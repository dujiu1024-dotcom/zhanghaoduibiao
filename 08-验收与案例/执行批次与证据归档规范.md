# 阶段 8 执行批次与证据归档规范

## 1. 执行批次

按以下批次执行；每批结束先归档证据，再进入下一批。遇到阻塞时记录原因，不得用模拟结果填补。

### 批次 A：环境与配置冻结
- 记录仓库 commit、TRAE 版本/运行模式、模型和参数、工作区信任状态。
- 保存 Rules、六类 Subagent、十项 Skills、MCP 配置快照。
- 保存知识库快照、RAG 代码 SHA、全部检索参数和索引版本。
- 生成 run_id，每次独立运行不得复用。

### 批次 B：系统能力与权限门禁
- 验证根级/项目 Rules 是否实际加载。
- 验证六类 Subagent 的识别、按需路由、独立交付和总控综合。
- 验证多专家黑板交接、冲突登记和总控裁决。
- 验证十项 Skills 的识别与组合调用。
- 对资金支出、正式发布、合同/报价承诺、敏感数据外发执行明确的拒绝/待审批负向测试。
- 每个动作记录“请求—风险等级—系统响应—是否执行—审批主体”。

### 批次 C：RAG 与知识迁移
- 先冻结正向、负向、对抗、独立保留四类题集和 gold 标注。
- 保留集不得进入提示、调参、索引调试和修正规则反馈。
- 运行时记录 SIM_FLOOR、ANSWER_MIN_COVERAGE、SHORT_RELAX、ENTITY_GATE 等真实值，不能只写默认值。
- 输出逐题候选、排序、回答、引用、拒答及错误归因。
- A-E 每层至少抽样；D/E 单独核验权限，原件 SHA 不变，未授权资料不得进入共享索引。

### 批次 D：五类案例盲测
- 每案独立新会话；先提供单一案例输入，冻结首轮输出。
- 由测试人员从工作区外的参考材料中选择反证，注入第二轮。
- 专家单项产物与总控最终综合结果分别留档、分别评分。
- 评分人员不得在首轮冻结前查看参考答案/挑战要点。
- 前四类不得读取个人专属知识；CASE-05 使用独立个人 IP 场景输入。

### 批次 E：问题修复、回归与结论
- 对失败逐项归类：Rules、Subagent、Skill、知识治理/RAG、案例输入、模型、TRAE 环境或外部依赖。
- 每项失败建立 Issue，写明复现条件、证据、影响和验收标准。
- 修复后执行定向回归及必要的相邻案例回归。
- 形成最终报告；未解决项列为阻塞/延期，不得以文档完整替代结果。

## 3. 运行编号与完整性

- 建议格式：S8-YYYYMMDD-CASE-01-001；系统测试可用 S8-YYYYMMDD-SYSTEM-001。
- 同一 run_id 对应唯一环境快照、输入版本和输出集合。
- 文件名包含 run_id、阶段和产物类型；原始日志只追加、不覆盖。
- 修订输出使用新版本号，保留旧版本及差异说明。
- 每次运行结束生成 manifest，记录文件相对路径、SHA-256、生成时间和保管位置。
- 任何缺失项写 not_collected 并说明原因，不得留空后默认为通过。

## 4. 运行状态枚举

- not_started：未开始。
- blocked_local_environment：被本机环境/权限阻塞。
- running：执行中。
- passed：证据满足验收标准。
- failed：已执行但不满足标准。
- not_applicable：经说明确认不适用。

“待用户真机验证”统一映射为 not_started 或 blocked_local_environment，并写明具体原因。
