## 二、B-08 专家冲突处理独立补测

### 测试概要

| 字段 | 值 |
|------|-----|
| 测试编号 | B-08 |
| 输入场景 | 虚构烘焙企业进入邻近城市 |
| 触发专家 | strategy-expert + competition-expert |
| 独立会话 | 在同一主会话中并行调用两个专家子 agent（Task tool + 不同 subagent_type） |
| 专家调用可观测性 | **NOT_OBSERVABLE** — Task tool 的 subagent_type 参数选择了对应专家类型，专家产出独立报告，但客户端无独立会话切换 UI 展示 |

### 两位专家的核心分歧

| 维度 | 战略专家推荐 | 竞争专家推荐 | 冲突类型 |
|------|------------|------------|----------|
| **进入模式** | 轻模式多点测试（外卖+代销+快闪），不直接开店 | 前置验证 + 窄任务单店轻量试点（1 家小面积试点店） | 根本分歧 |
| **是否需要先开店** | 反对开店，只做轻触点获取市场信号 | 建议开 1 家窄任务试点店 | 根本分歧 |
| **验证定位** | 验证本身就是 90 天的主要目标 | 验证是开店的前置条件 | 根本分歧 |
| **现金消耗** | 几乎零固定支出，变动成本挂钩销量 | 15-25 万启动投入 | 量级差异 |
| **品牌建设优先级** | 品牌可延后，先验证需求 | 窄任务定位本身就是差异化 | 逻辑分歧 |
| **前置调研** | 未强制要求 | 要求 5-7 天前置验证 | 流程分歧 |

### 总控冲突审查

#### 1. 冲突识别（明确不抹平）

- **冲突点 1：是否"需要"有一个物理门店** — 战略专家认为轻触点足够；竞争专家认为至少需要 1 家试点店才能真正验证。
- **冲突点 2：90 天的目标到底是"进入"还是"验证"** — 战略专家把验证当目标；竞争专家把验证当前置条件。
- **冲突点 3：现金的使用方式** — 战略专家极端保守（几乎不花钱）；竞争专家愿意投入 15-25 万但有止损阈值。
- **冲突点 4：竞争应对** — 战略专家对竞争者反应讨论较少；竞争专家详细推演了竞争者反应路径。

#### 2. 双方证据强度与缺失证据

| 专家 | 证据强度 | 缺失证据 | 可证伪条件 |
|------|---------|---------|-----------|
| 战略专家 | 高（结构严谨、覆盖全面） | 未做详细的竞品反应推演 | 若竞争专家的竞品反应推演是真实的，则"轻触点可能被竞争者忽略"的假设不成立 |
| 竞争专家 | 高（结构严谨、覆盖全面） | 未讨论"90 天时限内能不能完成前置调研+开店"的时间压力 | 若战略专家的时间窗口分析正确，则 5-7 天调研+开店在 90 天内太紧 |

#### 3. 三个选项公平比较

| 评估维度 | 直营进入（竞争专家路径） | 渠道试点（战略专家路径） | 暂缓进入 |
|----------|------------------------|------------------------|---------|
| 收益 | 若成功：跑通单店模型、品牌直接建立 | 若成功：获取多点市场信号 | 保留现金 |
| 成本 | 15-25 万启动 + 月度运营 | 几乎零固定成本 | 0 |
| 机会成本 | 钱花在一家店，无法多点探索 | 信息价值高，但品牌建设延迟 | 错失市场窗口（无证据证明确实有窗口） |
| 风险 | 高（选址错/品类错/竞争反应） | 中（信息失真） | 低 |
| 可逆性 | 中高（退出成本 6-15 万） | 极高（几乎零沉没成本） | 极高 |

#### 4. 最小取证计划

| 顺序 | 数据 | 获取方式 | 负责确认 |
|------|------|---------|---------|
| 1 | 邻近城市竞品真实数量、类型、分布 | 美团数据抓取 + 实地走访 | 研究专家 |
| 2 | 好位置租金和可获得性 | 中介扫街 | 选址人员 |
| 3 | 配送成本和时效 | 冷链物流询价 + 小批量测试 | 供应链 |
| 4 | 现有产品在邻近城市的口味适配度 | 街头试吃 30-50 人 | 市场人员 |

#### 5. 暂定建议与成立条件

> **暂定建议：先执行战略专家方案（轻模式多点测试），同时纳入竞争专家的前置调研和止损阈值。**
>
> **成立条件：** 执行中发现"无法落地任何轻触点"或"所有触点数据远低于盈亏平衡线"时，暂停进入，重新评估竞争专家方案。

#### 6. 明确需要用户批准的事项

- 任何预算支出 > 1 万元
- 任何对外签署合同或合作协议
- 任何涉及品牌形象的对外宣传

## 五、局限性声明

1. **独立会话隔离**：Trae 客户端不支持在同一窗口内创建真正独立的会话上下文。本次执行在主会话内依次进行，无法保证会话级别的隔离。Skill 之间通过工具调用隔离，但可能存在隐式的对话上下文串扰。

2. **Skill 加载状态展示**：Skill 加载可通过 Skill tool 返回的 Skill Path 和 Details 观测，但"加载"和"执行"的边界在当前架构中不清晰。Skill tool 返回的是 Skill 的定义框架，实际执行由 Task tool + 专家子 agent 完成。

3. **专家调用可观测性**：Task tool 的 subagent_type 参数选择了对应专家类型，专家产出独立报告。但客户端无 UI 层显示"当前正在调用哪个专家"。

4. **Trae 版本号**：未从客户端界面获取到，标记为 `unknown_not_exposed`。

5. **虚构数据声明**：所有测试输入均为 Issue 中给出的虚构案例。执行过程中未引入任何外部数据，未编造任何虚构市场数据。
