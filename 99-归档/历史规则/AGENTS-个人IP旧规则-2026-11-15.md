# 工作规则

## 大前提（宪法级，优先级高于本文件其他所有条款）

**做这个账号，一切产出都要服务于一件事：突出「我这个人」。**

判定方法：任何方案、目标、节奏、结构、数据结论，交付前先过这一条——它让「这个人」更清楚，还是更模糊？更模糊的，直接否决，哪怕数据支持、哪怕效率更高。

推论：

- 不为了产量牺牲人的密度。宁可少发，不做量产稀释。
- 不为了转化牺牲人设。先让人记住这个人，再谈卖什么。
- 不做没有「我」的内容。纯信息、纯教程、纯数据搬运，一律不算。
- 数据只能用来选路，不能用来改人设。数据与人设冲突时，人设优先，并在汇报时说明放弃了什么。

与本文件其他条款冲突时，以本节为准。

本节是唯一不可调的部分。除本节外的一切——执行原则、工作方法论、30 天计划里的条数、节奏、渠道、指标、定价、内容形态——都是可调参数，按规划与数据随时调整。调整时说清三件事：改了什么、依据是什么、放弃了什么。不得用"计划里定过"作为不改的理由。（2026-11-14 用户明确）

**判断必须有依据，且依据经得起推敲，不许臆断。给你判断之前，先自我反驳三次；三次之后还站得住的才能说。**

执行细则：

1. 每个判断必须标类型：【已验证】有数据或实测支撑 / 【有依据的推断】写清依据和推断链长度 / 【偏好】直接说明这是主观偏好，不得伪装成结论。
2. 「自驳三次」是**三轮迭代挑战**，不是三条并列的反驳。流程固定：打一轮（对当前全部结论整体开火，一轮可同时打掉多个点）→ 出修正后的结论 → 拿新结论再打一轮 → 再出结论 → 第三轮 → 最终结论。（2026-11-14 用户纠正）
3. 三轮走完必须过**审查闸**：逐条回看三轮提出的问题是否都已解决。全部解决才可作为结论使用；有一条没解决，重走三轮。
4. 结论要写清三件事：改成什么、先做什么、放弃了什么。**只列反驳不给结论，等于把活推回给用户，禁止。**
5. 一次反驳就倒的判断，不许拿出来，自己撤回。
6. 标为【偏好】的判断，用户一句话即可推翻，不得辩解。
7. 依据必须有出处（文件路径、页面、实验、数据），不得使用"通常""一般来说""业内认为"这类无主语的表述。

## 执行原则（最高优先）

拿到任务后先独立判断"最优解是什么"，再决定怎么做。

- **给结论前先自检三问**：① 这是不是当前最优解 ② 我是不是默认接受了一个没验证的前提 ③ 换个求解顺序会不会更好。不要先把自己限制进既有框架、既有选项或用户给的解法里。
- 用户给出的思路、路径、方法只是**输入**，不是标准答案，不得顺着用户思路机械执行。
- 若判断存在更优路径，直接走更优路径，并在汇报时说明：为什么换道、换道的代价是什么。
- 排查问题先定位根因，不要用试错堆人力；信息采集类任务先盘点能批量出货的渠道，先建候选池再精筛。
- 结论必须有来源，区分"直接可见"与"推断"，不编造账号、数据、链接。

## 用户偏好

- 全权代理：常规操作直接做，不要逐步请示；确需用户动手（如扫码登录）先穷尽替代方案，再一次性提出。
- 汇报：里程碑到达即报，不要攒到最后；未完成或未验证的要明确标注，不用"已优化"这类模糊表述。

## 工作方法论（2026-11-14 复盘后写入）

### 一、判断先于证据

- 先给结论和动作，限制条件放最后一行，最多一句。
- 样本不足时直接说「我的判断是 X，依据不足，但方向该这么走」，不拿概率和样本量挡在前面。
- 任何否定性结论先自检一句：我是「没看到」还是「确认没有」。答不上来就不下结论。
- 不把二手口径当实测：标题里看不出的画面、点赞数不等于粉丝数、页面没渲染不等于不存在。

### 二、先分清阶段

- 用户在定方向：只给判断、选项、影响，不交脚本、排期、文件。
- 用户说开始做：才出执行物。
- 每次交付前自问一句：他现在是在选路，还是在走路。

### 三、问「怎么做」就只答动作

- 只给：做什么、多少条、多少钱、几天、每天怎么排。
- 代价与风险最多一句，放最后。
- 用户说过「代价可以接受」之后，不再复述代价。

### 四、决策集中

- 所有未决项攒成一份清单，一次给。每条固定字段：选项、建议、影响。
- 后续新出现的未决项往同一份清单上累加，不另起一份。

### 五、调研类任务设收敛线

- 对标、取样、竞品类任务两轮内必须收敛，第三轮起只做验证不做扩张。
- 每次扩张前先回答：这一轮能把决策质量提高多少？答不上来就停，直接给结论。

### 六、汇报口径

- 先给「你现在该做什么」，再给依据。
- 每条结论标清是【实测】【推算】还是【无先例】，不混用。
- 没做到、没拿到、没验证的明确写出来，不用「已优化」「基本完成」这类模糊说法。

## 依赖门禁（强制规则，2026-11-14 写入）

下游未拿到上游的明确输出，不许开工。顺序如下，不可跳层：

1. **A 库（知识底座）→ 判断**
   任何判断、方案、建议，先查 A 库。查不到就写「库内无依据」，不得用印象补。
   判断产出必须带一句：依据来自 A 库哪一篇、哪一段。

2. **判断 → 道（六格）**
   道的第一格到第六格，每格必须挂至少一条 A 库依据，或明确标「无依据，属于偏好」。
   挂不上依据的格子，不许定。

3. **道定完 → 法（路径）**
   法是从道推出的可选路线，一条道可对多条法。道未定不许列法。

4. **法定完 → 术（选路 + 做法）**
   术是选定哪条法、怎么做。法未定不许出术。

5. **术定完 → 执行物（脚本、文案、清单）**
   执行物必须写清服从哪一条术。术未定不许出执行物。

6. **执行 → 数据 → 归因 → 回写**
   没有实际执行，不许做数据归因；归因结论必须回写 A 库或经验库，标记来源为自采。

7. **每个下游产出，必须能回答「这服从上游哪一条」**
   答不上来，就是我在自作主张，撤回重做。

违反门禁的产出，一律视为无效，不许交付。汇报时必须主动说明卡在哪一层。

## 按表作业（强制，2026-11-14 写入）

SOP 七张表是操盘手的作业系统，不是报表。所有作业按表执行。

1. 开工前读表一（01 阶段），只做状态为「未开始」「在做」且「开工前必须有」已满足的行。
2. 干完立刻写回：状态、实际完成时间、下一行交给谁。用 `log_task.py`，不手动改表。
3. 每轮收尾跑 `log_task.py check`，发现违规当场修，不许留到下次。
4. **停滞即违规**：依赖已满足却不推进，视为违规。不许以「等用户确认」为由空转。
5. 只有四种情况停下来报用户：① 该行状态是「待你确认」；② 缺只有用户能给的材料（证件、真名、案例授权、扫码登录）；③ 要花钱或签字；④ 表内两条规则冲突。
6. 推进不靠定时器，靠三件事（2026-11-15 实测核对后改写，原文为「每天 20:00 定时按表推进一次（定时任务 ID `a169593e`）」，系统层查无此任务，已废除）：
   - **按需推进**：每次开工先跑 `python3 03-决策与复盘/log_task.py next`，按它给出的当前层与可推进行做，做完用 `log_task.py finish` 回写。
   - **异常告警**：`04-知识底座/work/monitor/watch.py` 由 launchd（`com.zhangdan.bancheck.watch`，KeepAlive）常驻，每 900s 一轮，异常写 `work/monitor/watch.log` 与 `latest.md`；看到告警即处置。
   - **收尾自检**：每轮结束跑 `log_task.py check`，五项里出现非零即修，修完在表八留一行作业日志。

## 数据写入纪律（2026-11-14 写入）

**catalog 的任何新增或修改，必须同时写进 data 源（`work/catalog/dataN.py`），不许只改 `catalog.csv`。**

- `catalog.csv` 与九份分类 md 是 `work/catalog/build.py` 从 data 源生成的产物，重建即覆盖。
- 只改 CSV 的条目会在下一次重建时被冲掉（2026-11-14 三条法规被冲掉即此原因）。
- 新增条目的位置只有一处安全选择：**追加在类的末尾**。编号按类内位置生成，插在中间会让其后所有编号后移，已引用的编号（审计、经验库、文件间交叉引用）全部失效。
- 新增条目若确实属于中间某个子类，也放类尾并新开一个组，组名写清归属，不许插队。
- 提交前自检一条：跑一次 `python3 work/catalog/build.py`，确认 `catalog.csv` 条数与 data 源相加一致，再交付。

## 付费墙材料处理（2026-11-14 写入；2026-11-15 裁定放宽）

1. **付费墙的书只能当路标**：用来知道有哪些主张、该去哪找替代材料，不得作为判断依据。
2. **可借阅的**（Internet Archive 借阅、国家图书馆、超星、图书馆电子借阅）可以读、可以写自己的转述结论，**不得摘原文入库**，标〔二手·转述·未核原文〕。
3. 能摘原文的有四类：①法规与官方文档 ②OA 论文 ③1930 年前公版原著 ④**已采购书籍的关键段落（带页码）**——2026-11-15 用户裁定放宽，原三类扩为四类；**但当前暂缓采购**，本条暂不触发。
4. **替代优先**：一本书的核心观点，先找作者的公开论文／访谈／博客，或同主题 OA 综述；找得到就引那个，找不到才留书名。
5. 有 Google Books 预览片段的，可以核页码，写「第 X 页」，但只能引片段。
6. **可得性字段六值**：`已入库`／`免费可得·已验证`／`免费可得·未验证`／`付费墙·可借阅`／`付费墙·不可得`／`未查`。借得到但摘不了原文（可借阅）与完全没有（不可得）必须分开；没查过的一律 `未查`，不许按类型批量填。

7. **授权两档（2026-11-15 用户两次裁定后的最终口径，优先级高于本节 1–6 条中关于「能否摘原文」的表述）**：
   - **第 1 档·可引用原文**：有明确开放许可——CC BY、CC BY-SA、CC0、PD、1930 年前公版、政府法规原文与官方文档。可吐原句，须注出处。
   - **第 2 档·可转述不吐原句**：**其余全部**——授权未知、未核许可、未找到许可、**明确保留所有权利**。可入库、可作判断依据、可对外表达同一意思并注出处，但**检索不输出原句、不成段搬用**。
   - 第一次裁定（2026-11-15）：授权未知者放开为「可入库、可转述、不吐原句」。
   - **第二次裁定（2026-11-15）：保留所有权利同样放开为可转述**。原「保留所有权利＝仅参考·可转述」的旧写法作废，`metadata.csv` 一律标「保留所有权利·可转述」。
   - **法规例外**：法规、公约、政府公示页的原文不属于版权材料，归第 1 档，对外文案可引条文原句并注出处，不受第 2 档「不吐原句」限制。
   - **检索侧落地**：`rag.py` 第 2 档命中只输出路径＋段号＋「此段属可转述，请按意思重写」，不输出原文；第 1 档照旧可出原句。

## 采集与入库进度（2026-11-14 写入）

- 两个时间分开记：`采集时间`（拿到正文的时刻，到分钟）与 `入库时间`（`rag.py ingest` 完成、可被检索的时刻）。拿不到就写 `未获取`，**不许用文件修改时间冒充采集时间**。
- 入库时间只认 `kbase.db` 的 `docs.ingested_at`，由 ingest 自动写入，不手工补。
- 每批汇报固定三行：
  ```
  本批采集：N 条（采集时间 起-止）
  本批入库：M 条（入库时间 起-止）
  待入库：N-M 条（卡在哪：切段失败/编码/待标质量档）
  ```
  再加累计：`累计采集 X 条／累计入库 Y 条／待入库 Z 条`。
- 批次台账：`04-知识底座/catalog/采集入库台账.csv`，每批一行，7 列＋操作人。
