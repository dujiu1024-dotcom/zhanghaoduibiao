# 抖音「公开做产品 / 动手实现 / Agent 落地」对标调研

调研日期：2026-11-13
调研对象：为 FDE（Forward Deployed Engineer）人设账号找可对标学习的真实抖音样本
样本来源：抖音网页版真实页面（未登录），逐条打开作者主页/视频页/合集页核实
配套：[知识库](../../../04-知识底座/knowledge/INDEX.md)｜[候选池](../work/candidates.md)

## 一、先给结论

1. **这个方向在抖音没有跑出头部。** 用"Agent / AI编程 / 独立开发 / vibe coding / 手搓"等词在抖音合集库里能触达的同方向账号，粉丝集中在 400–9,000，唯一 5 万以上的是「技术爬爬虾」（51.6 万），而他的定位是"计算机知识与软件 DIY"，不是"我在做产品"。
2. **同方向内容被"教程/课程"占满，不是"过程记录"。** 分集标题高频词是「第 N 集」「保姆级」「零基础」「从0」，本质是课程目录，不是项目进度。
3. **真正"公开做东西"的只有极少数小号。** 简介明确写"分享用 AI 做东西的过程"的「冬天与云·AI」只有 8,625 粉、39 条作品。
4. **可迁移的叙事形式不在 AI 赛道，在过程型内容里。** 装修日记、30 天挑战、创业还债日记、服装店崩溃实录这批账号，把"连载"跑通了；它们的分集逻辑和时长分布可以直接搬到 FDE 三段式上。
5. **最危险的位置是"1 分钟左右的半教程"**：过程型样本里 15–30 秒（决策/挑战）和 2–6 分钟（冲突/故事）两头都成立，中间地带样本最少——而这恰好是"讲我怎么做 Agent"最容易滑进去的时长。

### 四条可量化迁移的结构

1. **时长两极，不要中间**：15–30 秒（一个决策/一个挑战动作）或 2–6 分钟（一个冲突/一段故事）。1 分钟左右的"半教程"在这批样本里最少。
2. **单集标题写"麻烦"，不写"进度"**：赵三登第 2 集叫"久违的拥抱"，Dou.有米第 1 集直接写崩溃事件；"第 N 集"只做索引。
3. **用数量/时间盒制造追更预期**：30 天卧推 100kg、挑战 100 款。观众知道什么时候能看到结果。
4. **把选择权交给评论区**：装修日记每集只问一个决策（岩板还是石英石），这就是 FDE 第①段"评论区出主意"的原生形态。

## 五、四维拆解：钩子 / 人话 / 系列 / 转化

### 5.1 前 3 秒钩子

| 类型 | 样本 | 证据 |
| --- | --- | --- |
| 认知纠正（幻灯片大字） | 东风第 1 集 | 【可见·截图】首帧纯色幻灯片，左上角一行大字，无真人 |
| 结果承诺 | 技术爬爬虾「Pi…保姆级攻略，一期精通」 | 【可见·标题】"一期精通" |
| 痛点共鸣 | AI编程自习室「做小程序被注册流程劝退？」 | 【可见·标题】 |
| 数字清单 | 冬天与云「8个设计效果词，让你的网站更高级」 | 【可见·标题】 |
| 冲突/出事了 | Dou.有米「崩溃的服装店主」 | 【可见·标题+首集文案】 |
| 未完成提问 | 珍珍「大家觉得这次我们会成功吗？」 | 【可见·标题】 |

**给 FDE 的取舍**：技术类样本用"认知纠正/结果承诺"，过程类样本用"冲突/提问"。FDE 要的是后者——前者吸来的是同行。

### 5.2 怎么把技术讲成人话

- **最好的一档**：AI编程自习室。把每个技术点翻译成业务症状——"页面能点，但订单只存在手机里老板看不到"（第 4 集标题）。观众不需要懂代码就知道这集解决什么。
- **中间一档**：冬天与云。把前端实现翻译成"你只要告诉 AI 这几个词"。
- **最差一档**：猪头肉配Codex / 东风。直接用 harness、幂等、veRL 做标题，观众必须先是同行。
- **规律**：标题里出现框架名和源码术语的账号，粉丝都在 3000 以下；标题里出现"你遇到什么麻烦"的账号，粉丝能到 8000 以上。

### 5.3 系列化

| 做法 | 样本 | 可迁移性 |
| --- | --- | --- |
| 第 N 集 + 统一封面模板 + 右侧连播 | 东风（8 集）、技术爬爬虾 | 高，纯形式 |
| 单项目贯穿，每集解决上一集遗留 | AI编程自习室（咖啡点单小程序 7 集） | 高，最适合"做一个 Agent" |
| 两段式课程（基础 → 进阶） | story maker（Agent 7 集 → RAG 3 集） | 中，偏课程 |
| 情绪节点做标题 | 赵三登 | 高，但需要真实情绪 |
| 数量目标做编号 | 这瓜子没肉、冰红茶 | 高，适合"做 10 个客户案例" |

### 5.4 评论区与私信转化

- **可见的转化位只有两个**：简介（AI编程自习室"承接各类软件定制"）、简介里的选题机制（猪头肉"评论或私信提需求，定期抽一个做成课程"）。
- **橱窗、置顶、直播、粉丝群在未登录状态下不渲染**，因此"有没有在卖课"这件事，本报告无法给出结论。
- 能确认的是：**这 9 个同方向账号里，没有任何一个把"加微信/领资料"写进简介**——要么不敢写，要么不需要。这既是空位，也说明平台对导流的限制。

## 六、能直接套 / 不能照搬

### 可以直接套到三段式的

1. **单项目贯穿 + 第 N 集 + 一集一个卡点**（AI编程自习室、东风的结构）→ 直接用作段②"过程"。
2. **时间盒 + 可验证数字**（30 天卧推 100kg）→ 把"做一个 Agent"改写成"14 天把某流程从 3 小时压到 10 分钟"。
3. **一集一个决策，把选择权交给评论区**（装修日记）→ 直接用作段①"想法的评论区出主意"。
4. **冲突第一句**（服装店崩溃）→ 用于段②的真实翻车现场。
5. **"情绪节点当标题"**（赵三登）→ 替代"第 3 集：继续开发"这种进度标题。
6. **简介第一行挂接单/选题机制**（AI编程自习室、猪头肉）→ 最低成本的转化位。

### 不能照搬的

| 做法 | 为什么不能 |
| --- | --- |
| 源码级/框架名标题（猪头肉、东风） | 观众被锁死在同行，粉丝 3000 以下，无法转化成客户 |
| 40 分钟长课（AI大模型-梨花诗、story maker 18 分钟） | 抖音的过程型样本里没有这个时长段跑通；长课是 B站逻辑 |
| 纯幻灯片不露脸（东风） | 建立不了"能交付"的信任，FDE 需要真人 + 现场 |
| "第 100 讲"式课程库（AI编程自习室 272 条） | 会把账号做成教辅，和 FDE 的"我在给客户做系统"人设冲突 |
| 探店/评测外壳（乔雅娴 832） | 同质化最严重，且稀释专业感，样本里粉丝最低 |

## 七、第一条视频的结构建议（30–45 秒，结果前置）

依据：过程型样本里 15–30 秒能装"一个决策"，2–6 分钟能装"一段故事"；第一条既要有结果又不能太长，取 38 秒。以下按秒切，可直接照着拍。

| 时间 | 画面 | 声音/字幕 | 目的 |
| --- | --- | --- | --- |
| 0–2s | 结果本身：屏幕上系统正在跑、或客户现场手机端出结果。**不要logo、不要片头、不要露脸打招呼** | 字幕大号：「3 小时的活，现在 11 分钟」 | 结果前置，前 2 秒给"这玩意能用" |
| 2–5s | 同一画面的另一半：左边旧流程（表格/微信截图），右边新流程 | 口播："这是一家做 XX 的公司，每天有个人专门干这个" | 让观众知道"关我什么事" |
| 5–8s | 你的脸（第一次出现），背景是客户现场或工位 | 口播："我进去待了两天，发现真正卡住的不是这里" | 建立"到场"的可信度，和纯教程号区分 |
| 8–12s | 手指屏幕/白板画一条流程线 | 口播："卡住的是第三步，他们每天要手工对一遍" | 抛冲突：不是技术难，是流程错 |
| 12–24s | 录屏加速：改的那一段（只给一段，不要给架构图） | 字幕给数字：原来 3 步 → 现在 1 步；错误率 X → Y | 过程只讲一个卡点，其余全砍 |
| 24–30s | 回到结果画面，同一动作再跑一次，计时器/计数器在动 | 口播："这是今天跑的第 47 单" | 结果复验，用"第 N 单"代替"效果很好" |
| 30–36s | 你的脸，正对镜头 | 口播："下一个我想做 XX 还是 YY，评论区说，票多的先做" | 互动钩子：给二选一，不给开放题（对应段①） |
| 36–40s | 屏幕：评论区置顶/主页简介特写 | 字幕："想要的，评论区置顶自取" | 转化入口，只出现一次，不喊"加微信" |

### 拍这条时的四条硬约束

1. **前 2 秒不能出现人脸和自我介绍。** 同行样本里"先自我介绍"的开头没有一条跑出来；过程型样本全是先给结果或先给冲突。
2. **过程段只留一个卡点。** 12–24 秒这 12 秒里出现两个以上技术点，就退回成"半教程"，落进样本里的空白时长区。
3. **互动钩子必须是二选一。** 开放提问（"你们觉得呢"）在装修日记这类样本里没有出现；出现的是"岩板还是石英石"这种具体选择。
4. **转化入口只出现一次，且不放口播。** 口播喊"加微信"在这 9 个同方向账号的简介里都没有出现；可确认的转化位只有简介和评论区置顶。

### 这条视频明确不做什么

- 不讲架构、不讲用了哪个模型/框架（源码级样本粉丝全在 3000 以下）。
- 不做"第 1 集"前缀（第一条没有系列上下文，编号只会增加理解成本）。
- 不放 40 秒以上的讲解段（长课形态在抖音过程型样本里没有跑通证据）。

## 八、空位在哪 / 最容易踩的坑

### 三个空位

1. **"客户现场"是空的。** 9 个同方向账号全在讲"工具怎么用/代码怎么写"，没有一个在讲"客户的流程长什么样、我进去改了什么、交付后谁在用"。FDE 的核心差异点恰好在这里。
2. **"可验证的结果"是空的。** 过程型样本靠"30 天/100kg"给结果，AI 样本只给"学会了吗"。把结果做成可验证的数字（处理时长、错误率、人工替代量），目前没人占。
3. **"连载 + 真人现场"的组合是空的。** 过程型有连载没技术，技术型有技术没连载。

### 三个坑

1. **同行自嗨**：讲 harness、veRL、Agent Loop，点赞几十，收藏比点赞高——观众在"存着以后学"，不会掏钱。判断信号：评论区全在问技术细节，没有人问"能不能帮我做"。
2. **滑成教程号**：一旦开始"第 100 讲"，算法会把你推给学习者，之后发"我接了个客户"反而不推。
3. **半教程时长**：1 分钟左右的"我又写了一段代码"，在过程型样本里是空白区，既没有决策的爽感，也没有故事的冲突。

## 八、附：可复现的采集方法

1. 打开 `https://www.douyin.com/htmlmap/collection_0_<1-50>`，每页 200 条合集名 + 合集 ID。
2. 按关键词筛（Agent / AI编程 / 独立开发 / vibe / 手搓 / 创业 / 日记 / 挑战 / 装修 / 第N集）。

4. 打开 `https://www.douyin.com/user/<sec_uid>` 核实粉丝、获赞、简介、作品数。
5. 打开 `https://www.douyin.com/video/<aweme_id>` 核实单条数据、章节要点、右侧系列列表。
